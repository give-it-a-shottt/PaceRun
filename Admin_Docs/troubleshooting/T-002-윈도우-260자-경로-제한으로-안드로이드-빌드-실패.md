# T-002 윈도우 260자 경로 제한으로 안드로이드 빌드가 실패한다

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과]
무슨 문제였나: 앱을 처음 빌드하는데 11분 뒤 "파일 이름이 260자를 넘는다"는 오류로 실패했다. 프로젝트 폴더는 짧은데도 빌드 중간 파일의 경로가 333자까지 길어졌다.
어떻게 해결했나: 빌드 도구(CMake)를 긴 경로를 다룰 수 있는 새 버전(3.31.6)으로 고정했다. 고정하는 설정은 `app/plugins/withCmakeVersion.js`에 있다.

## 개발자 상세
- 증상: `npx expo run:android` → `> Task :app:buildCMakeDebug[x86_64] FAILED`, `ninja: error: Stat(...RNGestureHandlerDetectorShadowNode.cpp.o): Filename longer than 260 characters`.
- 원인: C++ 빌드는 `android/app/.cxx/…/<라이브러리>_autolinked_build/CMakeFiles/…/C_/project/PaceRun/app/node_modules/<패키지>/…` 처럼 "빌드 폴더 경로 + 소스의 절대 경로"를 이어 붙인 곳에 중간 파일을 만든다. 윈도우 레지스트리의 긴 경로 허용(LongPathsEnabled)은 이미 켜져 있었지만, 안드로이드 SDK 기본 CMake 3.22.1에 들어 있는 ninja 1.10.2는 긴 경로를 지원하지 않는다.
- 살펴본 대안: 프로젝트를 더 짧은 경로로 옮기거나 가상 드라이브(subst)를 써도 301자라 260자 아래로 내려가지 않았다.
- 해결:
  1. SDK에 CMake 3.31.6 설치(`sdkmanager --install "cmake;3.31.6"`, ninja 1.12.1 포함).
  2. `app/plugins/withCmakeVersion.js`가 prebuild 때 `android/app/build.gradle` 끝에 `externalNativeBuild.cmake.version "3.31.6"`을 덧붙인다. `app.json`의 plugins에 등록돼 있다.
  3. 이전 빌드 캐시 `android/app/.cxx`를 지우고 다시 빌드 → `BUILD SUCCESSFUL`.
- 재발 방지: `android/` 폴더는 prebuild가 만드는 산출물이라 직접 고치지 않는다(지워져도 플러그인이 다시 넣는다). 다른 PC에서 처음 빌드할 때 CMake 3.31.6이 없으면 Gradle이 설치를 안내한다.
- 함께 한 일: 템플릿에 딸려 온 안 쓰는 네이티브 패키지(react-native-gesture-handler 등)를 지워 C++ 빌드 대상 자체도 줄였다.
