# D-005 소리 안내 타이밍은 "지금 시각으로 계산"한다

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과]
무엇을: "1초마다 숫자를 1씩 올리는" 방식이 아니라, 시작 시각과 지금 시각의 차이로 경과 시간 · 지금 구간 · 내보낼 안내를 그때그때 계산한다. (AI 위임 결정)
왜: 💡 비유: 초를 손가락으로 세면 한눈팔 때 틀리지만, 시계를 보면 언제 봐도 맞다. 화면이 꺼지면 앱의 타이머가 늦게 울릴 수 있는데, 시계를 보는 방식이면 늦게 불려도 답이 맞다.

## 개발자 상세
- 구조: `app/src/domain/`의 순수 함수가 (러닝 설정, 지금까지의 상태, 지금 시각, 새 위치)를 받아 (새 상태, 내보낼 안내 목록)을 돌려준다. 위치 갱신 콜백과 1초 타이머가 둘 다 이 함수를 부른다.
- 같은 안내가 두 번 나가지 않게, 이미 내보낸 안내의 키(예: `interval-3-start`)를 상태에 기록한다.
- 일시정지 시간은 "일시정지한 누적 시간"으로 빼서 경과 시간을 구한다.

| 후보 | 장점 | 단점 |
|---|---|---|
| A. 시각 기준 순수 함수 (선택) | 타이머가 밀려도 정확, 기기 없이 단위 테스트 가능 | 상태를 값으로 다뤄야 해서 설계가 필요 |
| B. setInterval로 1초씩 증가 | 쉬움 | 화면 꺼짐 · 절전에서 타이머가 밀리면 시간이 틀림 |
| C. 네이티브 서비스(Kotlin)로 타이머 | 가장 정확 | 네이티브 코드를 직접 관리해야 함 |

- 결과로 생기는 제약: 안내가 "정확히 그 초"가 아니라 다음 계산 시점에 나간다(위치 갱신 간격만큼 늦을 수 있음).
- 결과로 생기는 제약 2: 경과 시간이 폰의 시계에 기대므로, 뛰는 중에 시계가 바뀌면(손으로 시각을 바꿈, 큰 폭의 자동 맞춤) 경과 시간이 그만큼 어긋난다. 에뮬레이터가 멈췄다 풀리며 시계가 2시간 건너뛰었을 때 실제로 봤다(2026-11-23). 시계와 무관하게 흐르는 시간(부팅 뒤 흐른 시간)을 쓰면 막을 수 있지만, 앱이 꺼졌다 켜지면 기준을 잃어 복구에 쓸 수 없어 지금은 쓰지 않는다.
- 이 결정을 바꿔야 하는 조건: 실기기 테스트에서 화면 꺼진 동안 계산 함수가 몇 초 이상 불리지 않는 것이 확인될 때 → C 또는 주머니 모드(RUN_01_005).
