# D-004 기록은 폰에 먼저 저장한다

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과]
무엇을: 러닝 기록 · 계획 · 설정은 폰 안의 DB(SQLite)에 저장한다. 서버는 계정을 연결한 사람만 쓰는 사본이다. (AI 위임 결정 — 근거는 pacerun-design.md "로그인 없이 바로 시작", "오프라인 우선 기록")
왜: 로그인이 첫 관문이면 첫 러닝까지 멀어지고, 밖에서 인터넷이 끊겨도 기록이 사라지면 안 된다.

## 개발자 상세
| 후보 | 장점 | 단점 |
|---|---|---|
| A. SQLite (선택) | 러닝 1건에 위치 점 수천 줄을 넣고 조건으로 꺼내기 좋음, 트랜잭션 | 스키마 관리 필요 |
| B. 키-값 저장소(AsyncStorage) | 단순 | 위치 점을 1초마다 붙이기에 부적합(통째로 읽고 써야 함) |
| C. 서버에 바로 저장 | 폰 DB 불필요 | 로그인 · 인터넷 필수 → 기획과 충돌 |

- 러닝 중에는 약 1초마다 위치 점과 경과 시간 · 거리를 저장한다. 앱이 강제 종료돼도 status가 finished가 아닌 러닝이 남아 복구 창(RUN_02_003)을 띄울 수 있다.
- 결과로 생기는 제약: 폰과 서버에 같은 기록이 두 벌 있으므로 중복 방지 규칙이 필요하다(D-007).
- 이 결정을 바꿔야 하는 조건: 여러 기기에서 동시에 계획 · 설정까지 맞춰야 할 때.
