# D-006 액세스 토큰 + 리프레시 토큰

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과]
무엇을: 로그인하면 짧게 쓰는 출입증(액세스 토큰)과 출입증을 다시 받는 교환권(리프레시 토큰)을 함께 준다. 교환권은 한 번 쓰면 새것으로 바뀌고, 서버가 폐기할 수 있다. (AI 위임 결정)
왜: 💡 비유: 놀이공원 손목띠는 하루만 유효하게 하고, 연간 회원권으로 손목띠를 다시 받는다. 손목띠를 잃어버려도 피해가 짧다.

## 개발자 상세
- 액세스 토큰: JWT, 유효 30분, 서버 DB를 보지 않고 검증한다.
- 리프레시 토큰: 무작위 문자열, 유효 30일. 서버에는 해시만 저장한다. 쓸 때마다 기존 것을 폐기하고 새로 발급한다.
- 보관: 앱은 expo-secure-store. 웹은 액세스 토큰을 메모리에만 두고, 리프레시 토큰은 httpOnly 쿠키로 받는다(자바스크립트가 못 읽음).
- 비밀번호: argon2 해시.

| 후보 | 장점 | 단점 |
|---|---|---|
| A. 액세스 + 리프레시(교체) (선택) | 탈취 피해가 짧고 서버가 로그아웃시킬 수 있음 | 테이블 1개와 갱신 흐름이 늘어남 |
| B. 긴 액세스 토큰 하나 | 가장 단순 | 탈취되면 만료까지 막을 방법이 없음 |
| C. 서버 세션 | 폐기 쉬움 | 요청마다 DB 조회, 앱에서 쿠키 다루기 번거로움 |

- 결과로 생기는 제약: 앱은 401을 받으면 갱신을 한 번 시도하고, 실패하면 업로드를 대기열에 둔 채 다시 로그인을 기다린다(pacerun-design.md 동기화 규칙).
- 이 결정을 바꿔야 하는 조건: 1인 사용이라 갱신 흐름이 과하다고 판단되면 B로 줄일 수 있다(서버 `refresh_tokens` 테이블과 `/auth/refresh`만 걷어 내면 됨).
