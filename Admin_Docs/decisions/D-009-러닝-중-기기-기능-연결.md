# D-009 러닝 중 기기 기능(위치 · 음성 · 잠금화면 버튼)은 Expo 모듈만으로 잇는다

## 한눈에 보기 (코드 몰라도 OK)
상태: [보완]
무엇을: 화면이 꺼져도 위치를 받는 일, 안내를 말하면서 음악 볼륨을 잠깐 낮추는 일, 잠금화면의 [일시정지] / [재개] 버튼을 모두 Expo가 제공하는 모듈로 만든다. 직접 짠 안드로이드 코드는 없다. (AI 위임 결정 — 실기기 확인 전이라 [보완])
왜: 1주 일정에 혼자 만들고 코드는 AI가 쓴다. 직접 짠 네이티브 코드는 내가 읽고 고치기 어렵다.

## 개발자 상세
| 기능 | 방법 | 한계 · 확인할 것 |
|---|---|---|
| 화면 꺼진 상태의 위치 | expo-location 백그라운드 위치 + 포그라운드 서비스 알림("러닝을 기록하고 있어요") | 제조사 절전이 서비스를 죽일 수 있다 → 배터리 최적화 해제 안내, 실기기 15분 확인 |
| 음성 안내 | expo-speech(한국어 TTS) | 기기에 한국어 음성 데이터가 없으면 말하지 않는다 |
| 음악 볼륨 낮추기 | 안내를 말하는 동안 expo-audio로 무음 파일을 재생해 "다른 소리를 낮춰 달라"고 요청하고, 끝나면 멈춘다 | expo-speech가 안드로이드에서 볼륨 낮추기를 직접 요청하지 않아서 쓰는 우회 방법이다. 실제로 낮아졌다 돌아오는지 실기기 확인 |
| 케이던스 모드 | 메트로놈이 계속 울리므로 낮추지 않고 섞는다 | 안내와 음악이 같은 크기로 겹친다 |
| 잠금화면 버튼 | expo-notifications의 고정 알림 + 버튼(일시정지 / 재개). 위치 알림과 별개로 하나 더 뜬다 | 알림이 2개 보인다. 화면이 꺼진 채 버튼이 반응하는지 실기기 확인 |
| 강제 종료 뒤 | 마지막 저장이 30초 안이면 이어 가고, 아니면 "이어서 / 여기까지 저장"을 묻는다 | — |

| 후보 | 장점 | 단점 |
|---|---|---|
| A. Expo 모듈만 (선택) | 네이티브 코드를 관리하지 않는다. 빌드가 단순 | 볼륨 낮추기가 우회 방법, 알림 2개 |
| B. Notifee 등 다른 라이브러리 | 알림 1개에 버튼까지 | 라이브러리 유지 상태를 확인해야 하고 설정이 늘어난다 |
| C. Kotlin으로 서비스를 직접 작성 | 가장 확실(타이머 · 오디오 포커스 · 알림 하나) | 내가 읽고 고칠 수 없는 코드가 생긴다 |

- 이 결정을 바꿔야 하는 조건: 실기기에서 ① 화면 꺼진 동안 위치 · 안내가 끊기거나 ② 음악 볼륨이 낮아지지 않거나 돌아오지 않으면 B 또는 C를 검토한다. 그 전에 주머니 모드(RUN_01_005, Q-003)로 버틸 수 있는지 먼저 본다.
