# D-003 app · web · server 폴더를 서로 독립으로 둔다

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과]
무엇을: 저장소 하나 안에 앱 · 웹 · 서버 폴더를 두되, 서로의 코드를 가져다 쓰지 않는다. 셋이 지키는 약속은 API 목록 문서 하나다. (AI 위임 결정)
왜: 앱과 웹이 코드를 공유하게 묶으면 앱 빌드 설정이 복잡해져서, 1주 일정에서 막힐 위험이 크다.

## 개발자 상세
| 후보 | 장점 | 단점 |
|---|---|---|
| A. 폴더 3개 독립 (선택) | 설정이 단순, 각 폴더를 따로 설치 · 실행 | 시간 · 페이스 표시 같은 작은 함수가 앱과 웹에 따로 있음 |
| B. 워크스페이스 + 공유 패키지 | 타입 · 함수 한 벌 | Metro(앱 번들러)가 폴더 밖 패키지를 보도록 설정해야 하고 빌드 문제가 잦음 |
| C. 저장소 3개 | 완전 분리 | 문서(Admin_Docs)와 API 약속이 흩어짐 |

- 결과로 생기는 제약: API 형식을 바꾸면 api-list.md · 서버 · 앱 · 웹을 각각 고쳐야 한다. 리뷰어 R4가 이 셋을 비교한다.
- 이 결정을 바꿔야 하는 조건: 앱과 웹이 같은 로직(예: 주 계산)을 많이 쓰게 돼 중복이 부담될 때.
