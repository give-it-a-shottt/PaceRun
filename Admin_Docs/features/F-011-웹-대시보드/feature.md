## 한눈에 보기

무엇을: PC 브라우저에서 내 러닝 기록을 크게 보는 사이트. 앱에서 연결한 계정으로 로그인하면 월 · 년 단위 막대 차트(거리 / 횟수 / 시간), 주 목표를 채운 주, 최근 러닝 목록이 보이고, 러닝 하나를 누르면 큰 지도와 구간 표가 나온다. 💡 비유: 앱이 운동 중에 보는 손목시계라면, 웹은 집에 와서 펼쳐 보는 운동 일지다.
왜: 폰 화면으로는 한 주밖에 못 본다. 한 달 · 한 해를 한눈에 봐야 "꾸준히 하고 있구나"가 보인다(P3).

## 설계 의도 (AI 초안 — 사용자 위임, 확인 전)
출처: pacerun-design.md 0-3 벤치마킹 표("웹 대시보드"), 0-4 IA(WEB_01_001~003), 3장 화면별 그리드(웹 대시보드 · 웹 러닝 상세), decisions/D-006(웹의 토큰 보관)

- 이 기능이 해결하는 문제: 앱은 "이번 주"만 보여 준다. 길게 쌓인 기록을 돌아볼 곳이 없다.
- 완료 기준(무엇이 되면 끝인지):
  1. 이메일 + 비밀번호로 로그인한다(가입은 앱에서만). 틀리면 알려 준다. 로그인하지 않고 대시보드 주소로 가면 로그인 화면으로 보낸다.
  2. 대시보드에 월 또는 년 단위 막대 차트가 보이고, 거리 / 횟수 / 시간을 바꿔 볼 수 있다. 앞 · 뒤 기간으로 옮길 수 있다.
  3. 주 목표를 채운 주가 보인다(최근 8주의 달성 여부와 연속 주 수).
  4. 그 기간의 합계(거리 · 횟수 · 시간)와 평균 페이스, 지난 기간과의 페이스 비교가 보인다.
  5. 최근 러닝 목록이 보이고, 항목을 누르면 러닝 상세로 간다.
  6. 러닝 상세에 큰 지도(경로), 지표, 구간 표, 같은 모드 지난번과의 비교가 보인다.
  7. 새로 고침해도 로그인이 유지되고, [로그아웃]하면 로그인 화면으로 간다. 토큰을 브라우저 저장소(localStorage)에 두지 않는다.
- 화면: `/login`(WEB_01_001), `/`(WEB_01_002 대시보드), `/runs/:id`(WEB_01_003 러닝 상세)
- API: POST /auth/login · /auth/refresh · /auth/logout(쿠키 방식 — `X-Refresh-Mode: cookie`), GET /me, GET /stats, GET /runs, GET /runs/{id} — overview/api-list.md 그대로. 서버는 고치지 않는다.
- 데이터: 서버의 값을 읽기만 한다. 저장하는 것이 없다.

범위 밖(하지 않는 것)
- 웹에서 가입 · 비밀번호 바꾸기 · 기록 고치기(기획: 계정은 앱에서 만든다)
- 모바일 화면 크기 맞춤(기획: PC 1440 기준, 태블릿까지만)
- 배포(내 PC에서만 띄운다)

## 결과 (AI 작성 — 구현 후)
- 바뀐 파일 (모두 `web/` 아래 — 새로 만든 폴더다)
  - 계산(순수 함수): `src/domain/dashboard.ts`(기간 제목 · 막대 · 합계 · 평균 페이스와 지난 기간 비교 · 기간 옮기기), `weeks.ts`(주 목표 카드: 최근 8주와 연속 주 수), `runView.ts`(러닝 목록 한 줄 · 러닝 상세 · 지난번 비교 · 모드별 목표), `loginForm.ts`(입력 확인 · 실패 문구), `format.ts`(숫자 · 날짜 표기), `types.ts`(서버 응답의 모양)

  - 설정: `vite.config.ts`(개발 서버가 `/api`를 내 PC의 API 서버로 넘김, 테스트 설정), `scripts/vitest.mjs`(T-001), `README.md`

- 실제 구조
  - 화면은 값을 계산하지 않는다. `describeDashboard()` · `describeGoalWeeks()` · `describeRunDetail()`이 만든 글자와 숫자를 그린다(앱과 같은 방식). 조회는 TanStack Query가 맡고, 조회 함수는 `api/runs.ts`에 있다.
  - 토큰(D-006의 웹 쪽): 액세스 토큰은 메모리에만 둔다. 리프레시 토큰은 서버가 주는 httpOnly 쿠키로만 다녀서 자바스크립트가 읽을 수 없다(localStorage · sessionStorage를 쓰지 않는다). 새로 고침하면 메모리가 비므로 사이트를 열 때 쿠키로 액세스 토큰을 다시 받는다. 조회가 401을 받으면 한 번 다시 받아 보내고, 그래도 안 되면 로그인 화면으로 간다. 쿠키 갱신이 401이면 0.3초 뒤에 한 번 더 해 본다(탭 두 개가 동시에 갱신한 경우). 사이트를 열 때 서버에 닿지 못하면 로그인 화면으로 보내지 않고 "서버에 연결하지 못했어요"와 [다시 시도]를 보여 준다. 로그아웃은 서버가 쿠키를 지워야 끝난다 — 서버에 닿지 못하면 로그아웃하지 못했다고 알리고 로그인된 채로 둔다.
  - 쿠키가 실리려면 사이트와 API의 주소가 같아야 한다(쿠키가 SameSite=Lax다). 그래서 개발 중에는 브라우저가 사이트와 같은 주소의 `/api`로 보내고 개발 서버가 API 서버로 넘겨 준다. CORS 설정도 필요 없다. API를 다른 주소에 둘 때(`VITE_API_URL`)는 사이트와 같은 사이트(예: `app.example.com`과 `api.example.com`)여야 새로 고침 뒤에도 로그인이 유지된다.
  - 대시보드의 기간 · 단위 · 보는 값은 주소(`?period=year&anchor=2026-01-01&metric=count`)에 둔다. 새로 고침 · 뒤로 가기에 남는다.
  - 주 목표 카드(최근 8주 · 연속 주 수)는 서버 통계에 없는 값이라 러닝 목록을 26주 전까지 읽어 웹에서 센다. 그래서 연속 주 수는 26주까지만 센다.
  - 러닝 상세의 "지난번 비교"는 목록을 최신순으로 넘기며 같은 모드의 바로 앞 기록을 찾는다(찾으면 멈춘다).
  - 차트(recharts)와 지도(leaflet)는 그 화면에 들어갈 때만 불러온다. 받지 못하면 그 자리만 "불러오지 못했어요"를 보여 주고(오류 경계), 사이트의 나머지는 그대로 쓴다.
  - 기준 날짜는 서버가 받는 범위(2000-01-01 ~ 오늘) 안으로 맞춘다. 더 갈 수 없으면 [이전] · [다음]을 누를 수 없다.
- 설계 의도와 다른 점
  - "기록" 화면(`/runs`)을 더했다. 기획의 화면 목록에는 없지만 피그마의 상단 메뉴에 "기록" 탭이 있고 러닝 상세의 길잡이가 "기록 › …"이다. 대시보드의 표와 같은 표에 [더 보기]를 붙였다(기획의 쪽 번호 대신). (AI 위임 결정)
  - 막대 차트의 목표선("1회 목표 3 km")과 범례는 그리지 않았다. 목표 거리 값이 서버에 없다 → Q-011.
  - 러닝 상세: 피그마의 넷째 지표("평균 발걸음")는 앱이 재지 않아 없다. 대신 모드별 목표를 제목 아래 한 줄로 보여 준다("목표 · 1분 달리기 + 1분 30초 걷기 × 8" — 기획의 "모드별 결과"). 비교 상자의 아이콘은 뺐다.
  - 합계 카드의 라벨은 "횟수"다(피그마는 "러닝"). 모드 배지는 "페이스메이커"로 적는다(피그마 · 앱의 배지는 "페이스").
  - 기간을 옮기는 꺾쇠 버튼 두 개, 막대에 마우스를 올리면 뜨는 도움말, 읽는 중 자리 표시, "불러오지 못했어요"와 [다시 시도], 빈 상태 문구("이 기간에는 기록이 없어요" · "아직 러닝 기록이 없어요" · "이 러닝에는 경로 기록이 없어요" · "기록을 찾지 못했어요"), Footer("© Pace Run")는 피그마에 없다. 문구는 AI가 지었다.
  - 평균 페이스는 "그 기간의 합계 시간 ÷ 합계 거리"다(인터벌의 걷기 구간도 들어간다). 지난 기간과 견줘 "지난달보다 7초 빨라졌어요"를 만든다.
  - 지도는 OpenStreetMap의 지도 그림을 쓴다. 러닝 상세를 열면 브라우저가 `tile.openstreetmap.org`로 요청을 보낸다(경로 근처의 지도 조각 주소가 그쪽에 남는다).
  - 글꼴은 Pretendard 3종을 사이트에 함께 싣는다(파일당 약 770 kB — 줄이지 않았다).
  - "오늘"은 대시보드를 연 때로 고정된다. 자정을 넘겨 열어 두면 새로 고침해야 바뀐다.
- 브라우저(머리 없는 Chrome) + 내 PC의 서버로 확인한 것 (2026-11-23)
  - 로그인하지 않고 `/`로 가면 `/login`으로 간다. 빈 칸으로 누르면 칸마다 안내, 틀린 비밀번호는 "이메일 또는 비밀번호가 맞지 않아요"
  - 로그인 → 대시보드: "2026년 · 11월 기록", 일별 거리 막대와 값, 주 목표 카드, "이번 달 18.9 km · 6회 · 2시간 2분", 평균 페이스 6'31"/km, 최근 러닝 5개(앱에서 올린 기록 그대로)
  - 년 · 시간으로 바꾸면 "월별 시간 (분)" 12칸, [이전 해] → "2025년 기록 · 이 기간에는 기록이 없어요". 주소에 `period` · `anchor` · `metric`이 남음
  - 기록 → 목록 8건 → 한 건을 누르면 러닝 상세: 지도에 경로와 출발 · 도착 표시, 지표, 구간 표, "첫 페이스메이커 기록이에요" / 다른 러닝은 "지난번보다 페이스가 15초 빨라졌어요 · 같은 자유 러닝 기준 · 6'50" → 6'35"", 경로가 없는 러닝은 "이 러닝에는 경로 기록이 없어요"
  - 새로 고침해도 로그인이 유지되고, localStorage · sessionStorage는 비어 있다. 없는 번호 · 틀린 모양의 번호는 "기록을 찾지 못했어요". [로그아웃] → `/login`, 그 뒤 `/runs`로 가면 `/login`
  - 너비 900에서 차트와 카드가 위아래로 쌓이고 옆으로 넘치지 않음
