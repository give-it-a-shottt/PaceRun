## 지적
- [신규] [제안] [확실] 쪽 넘기기 상한(MAX_PAGES 20 x 100줄 = 2,000건)에 닿으면 아무 알림 없이 멈춘다. `fetchRunsSince`는 그때까지 모은 것만 돌려주고, `fetchPreviousComparable`은 null("지난 기록 없음")을 돌려준다 — 위치: web/src/api/runs.ts `runPages` · `fetchRunsSince` · `fetchPreviousComparable` — 확인한 범위: 52b7e5a의 runs.ts 전체를 읽음. 기록이 2,000건을 넘는 경우는 패킷에서도 "확인하지 못한 것"(수백 건)에 속함 — 고치는 방법: 지금은 그대로 두고 한계를 feature.md나 코드 주석에 적어 두거나, 상한에 닿았을 때 "일부만 반영했어요" 같은 표시를 하는 것을 나중에 검토.
- [신규] [제안] [확실] 실패 처리 분기 가운데 화면 쪽에 있는 것은 테스트가 없다. `ErrorBoundary.retryPart`(조각만 한 번 다시 받고, 두 번째 실패면 새로 고침)의 상태 전환, `LoginPage`의 `toLoginFailure`(오류 객체 → 실패 종류 매핑), `AppLayout.handleLogOut`의 실패 표시 — 위치: web/src/components/ErrorBoundary.tsx, web/src/pages/login/LoginPage.tsx, web/src/components/AppLayout.tsx — 확인한 범위: 세 파일의 코드와 패킷의 테스트 목록(화면 컴포넌트 테스트 없음, D-001의 결정과 관련)을 확인 — 고치는 방법: 화면 테스트 도구를 들이지 않는 D-001을 유지한다면, `retryPart`의 결정 부분(다시 받을지 새로 고칠지)이나 `toLoginFailure`를 순수 함수로 빼서 테스트하는 방법이 있음. 지금 상태에서도 브라우저 실행으로 로그아웃 실패 · 서버 끔 경로는 확인했으므로 급하지 않음.

- 프론트 로딩 상태 → RunsTable.tsx `LoadedRunsTable`(스켈레톤 + LoadingText), ChartCard.tsx `ChartArea`, RunDetailPage.tsx `RunDetailSkeleton`, cardState.ts, guards.tsx `SessionLoading`, 조각 불러오기 Suspense fallback → 처리함
- 프론트 에러 상태 → LoadState.tsx `LoadError`/`ErrorNotice`, RunsPage `MoreRows`(다음 쪽 실패), RunDetailPage(404·422는 "기록을 찾지 못했어요", 그 밖의 실패는 다시 시도), cardState.ts `failed`(실패한 것만 다시 읽음), queryClient.ts `hasFailed`·`isShownFailure`(값이 있으면 다시 읽기 실패해도 값 유지, 로그인 풀림은 로그인 화면으로), ErrorBoundary(조각 못 받음 vs 그리기 예외 구분, 라우트별 key), 지난번 비교 조회 실패는 비교 상자만 생략 → 처리함
