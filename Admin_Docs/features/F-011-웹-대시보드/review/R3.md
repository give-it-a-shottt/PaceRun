## 지적 (있을 때)
- [주의] [확실] 화면 그리는 중 오류를 잡는 곳이 없다. 차트·지도 조각(`lazy(() => import(...))`)을 못 받으면(네트워크 끊김, 배포로 파일 이름이 바뀜) `Suspense`는 로딩만 처리하고 오류는 위로 던져, 앱 전체가 빈 화면이 된다. 이 경우 "불러오지 못했어요 · 다시 시도"로 이어지지 않는다 — `web/src/App.tsx`, `pages/dashboard/DashboardPage.tsx`(MetricBarChart lazy), `pages/runDetail/RunDetailPage.tsx`(RouteMap lazy) — 패킷 diff 전체와 `git grep ErrorBoundary|errorElement|onerror`(dafd668, web/src)로 확인, 결과 0건 — 라우트 바깥이나 차트·지도 자리에 ErrorBoundary(또는 react-router의 `errorElement`)를 두고 `LoadError` 문구와 새로 고침 버튼을 보여 준다.
- [제안] [확실] 404/422를 "기록 없음"으로 보는 판단(`isNotFound`)과 대시보드 주 목표 카드의 상태 조합(통계·러닝 목록 둘 다 있어야 ready, 하나라도 실패하면 failed)이 컴포넌트 안에 있어 테스트로 묶이지 않는다. 앞은 `queryClient.ts`의 `hasFailed`처럼 `app/`이나 `domain/`의 순수 함수로 빼면 D-001(화면 테스트 도구 없음)을 지키면서 테스트할 수 있다 — `RunDetailPage.tsx`(isNotFound), `DashboardPage.tsx`(goalState) — 두 파일 diff 전체와 패킷의 테스트 목록으로 확인 — 순수 함수로 빼서 단위 테스트 추가.
- [제안] [확실] `restoreSession`에서 "쿠키로 토큰은 받았는데 `/me`가 실패하는 경우"를 다루는 테스트가 없다(코드는 catch로 signedOut 처리). `fetchStats`·`fetchRun`도 테스트가 없지만 주소 조립뿐이라 위험은 낮다 — `api/session.ts`(restoreSession), 패킷의 session.test 17개 설명 — 코드와 패킷의 테스트 목록으로 확인, 테스트 파일은 직접 열지 않음 — session.test에 "/me 실패" 1건 추가.
- [제안] [추정] 서버가 잠깐 느리거나 꺼진 상태로 사이트를 열면 `restoreSession`이 `NetworkError`도 "로그인 안 됨"으로 처리해 로그인 화면으로 보낸다(문서의 "던지지 않는다" 설계, 테스트도 있음). 쿠키가 살아 있는 사용자는 로그인 화면에서 비밀번호를 다시 쳐야 한다. 실제로 거슬리는지는 서버를 끈 채로 열어 봐야 [확실]이 된다(패킷도 이 상황은 코드·테스트로만 확인) — `api/session.ts` restoreSession — 코드 확인, 실행하지 않음 — 서버 오류/연결 실패일 때는 signedOut 대신 "서버에 연결하지 못했어요 · 다시 시도" 화면을 두는 방안.
