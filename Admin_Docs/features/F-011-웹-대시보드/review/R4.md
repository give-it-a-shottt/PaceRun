## 지적 (있을 때)
- [신규] [제안] [확실] 러닝 목록 넘기기의 쪽 수 상한(MAX_PAGES 20 × 100건 = 2000건)에 닿으면 조용히 멈춰서 결과가 틀릴 수 있다 — web/src/api/runs.ts `runPages` · `fetchRunsSince` · `fetchPreviousComparable` — 패킷 diff로 코드를 직접 읽음(서버 `GET /runs`의 limit 1~100 · next_cursor 계약은 맞음. 2000건 넘는 데이터로는 실행하지 않음) — `fetchRunsSince`는 상한에 닿으면 26주 안의 러닝이 일부 빠진 목록을 그대로 돌려주어 주 목표 카드가 틀리고, `fetchPreviousComparable`은 상한에 닿아도 null("첫 기록이에요")을 돌려준다. feature.md "설계 의도와 다른 점"에는 26주 상한만 있고 이 2000건 상한은 없다. 상한에 닿았는지(`next_cursor`가 남았는지)를 돌려줘 화면이 "일부만 읽었어요"를 알리게 하거나, 최소한 feature.md에 상한을 한 줄 적는다. 1인 사용 · 현재 기록 수에서는 닿지 않으므로 급하지 않다.
