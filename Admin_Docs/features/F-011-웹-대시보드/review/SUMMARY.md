## 최종 판정 (AI 위임 판정 — 사용자 확인 전)
- 수용할 지적과 이유: 13개 가운데 9개를 고쳤고 1개는 일부만 고쳤다.
  - HTTP 상태 판정을 `api/client.ts` 한 곳에 모았다(`isUnauthorized` · `isClientError` · `isServerError` · `isNotFound`). 1차에서는 "쓰는 곳이 적다"고 거절했는데, 두 번 연속 같은 지적이고 실제로 숫자 401이 따로 남아 있어서 뒤집었다.
  - 로그인 지키기 파일을 `components/SessionGuards.tsx`로 옮겼다. 이제 `components/` → `app/` 한쪽으로만 부른다.
  - 날짜 표기를 `formatMonthDay` 하나로, 대시보드의 "읽는 중" 판정을 `cardStateOf`로 맞췄다. 주석의 "26주"는 상수 이름을 가리키게 고쳤다.
  - `npm audit`(개발용 포함)을 돌렸다: 취약점 0개.
  - 러닝 상세가 그릴 값을 기억해 두게 했다(같은 러닝이면 경로 배열을 다시 만들지 않는다).
  - 2000건 한계: 코드 주석과 feature.md에 적었다. 알림은 만들지 않았다 — 주 3회씩 12년을 뛰어야 닿는 숫자다.
  - (일부) 화면 쪽 실패 분기 테스트: 로그인 오류 바꾸기를 `api/failures.ts`로 옮겨 테스트 3개를 붙였다. 나머지 둘은 아래 거절.
- 거절할 지적과 이유:
  - `ErrorBoundary` · `AppLayout`의 화면 테스트: 웹에는 화면을 그려 보는 테스트 환경(브라우저 흉내 · 테스트 라이브러리)이 없다. 두 군데를 위해 패키지를 더하지 않았다. 두 동작은 브라우저에서 직접 확인했다(1차 반영 때: 서버를 끄고 로그아웃 → 안내 문구).
  - 클래스 이름 이어 붙이기 함수: 곳마다 한 줄이고 모양이 달라(조건 하나 / 둘 / 삼항) 함수를 만들어도 줄어드는 것이 거의 없다.
  - 테스트용 함수 내보내기: 1차와 같은 이유(테스트마다 모듈을 새로 불러오면 테스트가 더 읽기 어렵다).
  - 지난번 기록 찾기: 1차와 같은 이유(서버에 "이 시각보다 앞의 같은 모드 한 건" 조회가 없다. 1인용이라 1~3번 요청으로 끝난다).
- 다음에 고칠 것: Q-011의 답에 따라 목표선을 긋는다(서버에 값이 필요하다). 기록이 수천 건이 되면 서버에 "지난번 한 건" 조회를 만든다.
