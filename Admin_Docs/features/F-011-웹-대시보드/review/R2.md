## 지적 (있을 때)
- [제안] [확실] 로그아웃 요청이 서버에 닿지 못하면 화면만 로그인 화면으로 바뀌고 httpOnly 리프레시 쿠키는 브라우저에 남는다. 그 뒤 같은 브라우저로 사이트를 다시 열면 `restoreSession()`이 그 쿠키로 다시 로그인한다. 공용 PC에서 "로그아웃했다"고 믿고 자리를 뜨면 다음 사람이 기록을 볼 수 있다(코드 주석에 알고 둔 동작이라고 적혀 있고, 서버가 꺼져 있을 때만 생긴다) — `web/src/api/session.ts` `logOut()`, `web/src/components/AppLayout.tsx` `handleLogOut` — 패킷 diff로 두 함수와 `restoreSession()`을 읽음. 서버 `auth.py`의 logout이 쿠키를 지우는 것은 응답이 와야 된다는 것만 확인 — 서버에 닿지 못했을 때만 로그인 화면에 "서버에 연결하지 못해 이 브라우저의 로그인이 남아 있을 수 있어요" 안내와 [다시 시도]를 보여 준다(그대로 둔다면 feature.md에 알려 둔 것으로 적는다).
- [제안] [확실] 글꼴 3개(Pretendard Regular · Medium · SemiBold)가 글자를 전부 담은 woff2라 하나에 약 770KB, 합쳐 약 2.3MB다. `@font-face`에 `unicode-range` 분할이 없어 처음 여는 사람은 굵기마다 파일 하나를 통째로 받는다(이후는 캐시) — `web/public/fonts/*.woff2`, `web/src/styles/global.css`의 `@font-face` 3개 — `git ls-tree -l`로 파일 크기, `git show`로 `@font-face` 규칙만 확인(글꼴 값 · 모양은 보지 않음) — Pretendard의 서브셋판(KS X 1001 한글 2,350자 + 영문 · 숫자, 하나에 약 200~300KB)이나 `unicode-range`로 나눈 동적 서브셋판을 쓴다.
- [제안] [추정] 오래된 러닝의 상세를 열면 `fetchPreviousComparable()`이 목록을 최신 쪽부터 넘기므로, 그 러닝보다 새 기록이 든 쪽을 모두 읽은 뒤에야 찾는다(최대 20번 × 100개). 지금 기록 수(수십 건)에서는 1번이고, 수백 건이어도 몇 번이라 당장 문제는 아니다 — `web/src/api/runs.ts` `fetchPreviousComparable()` — 패킷 diff로 함수만 읽음. 서버 `GET /runs`가 시각 기준으로 시작점을 줄 수 있는지(`before` 같은 조건이나 그 러닝 위치의 cursor)는 열지 않았다. 서버 `runs.py`의 목록 조건을 확인하면 [확실]이 된다 — 기록이 많아지면 서버에 "이 시각 앞의 같은 모드 기록" 조건을 더하거나, 그 러닝의 시각에서 시작하는 cursor로 넘긴다.
- [제안] [추정] 지도 타일 주소가 `https://{s}.tile.openstreetmap.org/...`(a · b · c 하위 도메인)다. HTTP/2에서는 하위 도메인을 나눠도 빨라지지 않고 연결만 3개로 늘며, OpenStreetMap은 하위 도메인 없는 `tile.openstreetmap.org`를 권한다고 알고 있다 — `web/src/pages/runDetail/RouteMap.tsx` `OSM_TILE_URL` — 코드만 읽음. OSM 타일 이용 정책 문서는 지금 열어 보지 않았다(확인하면 [확실]) — `https://tile.openstreetmap.org/{z}/{x}/{y}.png`로 바꾼다.
