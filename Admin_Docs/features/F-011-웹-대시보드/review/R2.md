## 지적 (있을 때)
- [신규] [제안] [추정] 패키지 취약점 확인이 `npm audit --omit=dev`(배포용 의존성)뿐이다. 지금 실제로 띄우는 것은 vite 개발 서버(devDependencies: vite 8.3 · vitest 5.1 등)라 개발용 의존성의 취약점은 확인되지 않았다 — web/package.json, 패킷 "테스트 · 실행 결과" — package.json과 패킷의 audit 명령만 봄, audit을 다시 돌리지 않음 — `npm audit`(dev 포함)을 돌려 0이면 [확실]히 해소된다. 결과를 패킷 · feature.md에 함께 적는다.
- [제안] [확실] 러닝 상세의 "지난번" 찾기가 목록을 최신 쪽부터 넘겨, 오래된 기록일수록 상세를 열 때마다 순차 요청이 늘어난다(쪽당 100개, 최대 20번). 조회 키가 러닝마다 달라(`['run', id, 'previous']`) 다른 상세에서 이미 받은 쪽도 다시 받는다 — web/src/api/runs.ts `fetchPreviousComparable` · `runPages`, web/src/pages/runDetail/RunDetailPage.tsx `previousQuery` — diff로 확인, 기록 수별 실제 요청 수는 측정하지 않음 — 지금 기록 수(수십~수백 건)에서는 1~3번이라 그대로 둬도 된다. 기록이 늘면 서버에 mode · started_at 이전 조건의 조회를 더하는 것을 다음 서버 작업 후보로 적어 둔다(패킷에 "서버에 그런 조회가 없다"로 알려진 한계).
- [신규] [제안] [추정] RunDetailPage가 그릴 때마다 `describeRunDetail`을 새로 불러 `view.path`(와 `path[0]` · 끝점)가 매번 새 배열이 된다. 그래서 RouteMap의 `bounds` useMemo가 다시 계산되고, react-leaflet의 Polyline · Marker가 새 positions를 받아 다시 그릴 수 있다(지난번 조회가 끝날 때 등 몇 번뿐이라 체감 영향은 작다) — web/src/pages/runDetail/RunDetailPage.tsx `RunDetailPage`, web/src/domain/runView.ts `describeRunDetail`(path: `run.route.map(...)`), web/src/pages/runDetail/RouteMap.tsx — 새 배열이 생기는 것은 코드로 확인, react-leaflet이 참조 비교로 setLatLngs/setLatLng를 부르는지는 라이브러리 소스를 열지 않음(확인하면 [확실]) — RunDetailPage에서 `useMemo(() => describeRunDetail(run, previous), [run, previous])`로 감싸거나 path만 run.route에 묶어 memo한다.
