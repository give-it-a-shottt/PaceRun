## 한눈에 보기
상태: [통과] (2차 리뷰까지 끝, 실기기 소리 확인 전)
무엇을: 화면을 안 보고 뛸 수 있게 하는 세 가지 소리 안내. 인터벌은 구간이 바뀔 때와 끝나기 10초 전에 말해 주고, 발걸음 박자는 박자 소리를 계속 울려 주고, 페이스메이커는 목표 페이스에서 벗어났을 때만 말해 준다. 💡 비유: 옆에서 같이 뛰며 "이제 걷기", "조금 천천히"라고 말해 주는 사람.
왜: 뛰는 중에 폰 화면을 보지 않게 하는 것이 이 앱의 핵심이다(우선순위 1 · 2).

## 설계 의도 (AI 초안 — 사용자 위임, 확인 전)
출처: pacerun-design.md 0-5 Flow B(모드별 안내), 0-6(메트로놈은 오디오 파일 반복), 5장 RUN_01_002, 7장(레인 · 페이스 게이지), D-005

- 이 기능이 해결하는 문제: 뛰는 중에 지금 달릴 차례인지 걸을 차례인지, 박자가 맞는지, 너무 빠르거나 느린지 알려면 화면을 봐야 한다.
- 완료 기준(무엇이 되면 끝인지):
  1. 인터벌: 구간이 시작될 때 "달리기. 1분"처럼 말하고, 구간이 끝나기 10초 전에 "10초 뒤 걷기"라고 예고한다. 모두 마치면 한 번 알린다. 화면에는 지금 구간의 남은 시간(크게), 다음 구간, 구간 띠(레인)가 보인다.
  2. 인터벌 구간마다 달리기 · 걷기와 그동안 뛴 거리를 기록에 남긴다.
  3. 발걸음 박자: 정한 걸음 수(분당 150~190, 5 단위)의 박자 소리가 화면이 꺼져도 밀리지 않고 울린다. 일시정지하면 멈추고 재개하면 다시 울린다. 5분마다 시간 · 거리를 말한다.
  4. 페이스메이커: 최근 20~30초의 페이스가 목표에서 ±10초 넘게 벗어나면 "조금 천천히 / 조금 빠르게"라고 말한다. 같은 안내는 30초 안에 되풀이하지 않는다. 범위 안이면 1km마다만 말한다. 화면에는 지금 페이스(크게)와 목표 띠 게이지, "+8초 느림" 같은 글자가 보인다.
  5. 세 모드 모두 목표(일정 · 시간 · 거리)를 채워도 자동으로 끝내지 않는다. 채웠다고 한 번 알리고, 직접 끝낼 때까지 기록한다. 더 뛰는 동안에는 거리 안내(km)만 이어 간다. 발걸음 박자는 박자 소리와 5분마다의 시간 · 거리 안내를 그대로 계속한다(Q-009).
  6. 안내는 "지금 시각"으로 계산한다. 타이머가 늦게 불려도 지나간 안내를 몰아서 말하지 않고, 같은 안내를 두 번 말하지 않는다.
  7. 음악을 듣는 중이면 안내하는 동안만 음악 볼륨을 낮춘다. 발걸음 박자 모드에서는 박자 소리가 끊기지 않게 낮추지 않고 섞는다.
- 화면: `/run/active`(러닝 중)에 모드별 표시를 더한다 — 인터벌은 레인, 페이스메이커는 게이지. 새 화면 · 라우트는 없다.
- API: 없음(폰 안에서만 동작)
- 데이터: run_segments에 kind = run / walk 구간을 쓴다(테이블 변경 없음).

## 실기기 확인 목록 (사용자 — 에뮬레이터는 소리를 들을 수 없다)
- 인터벌: 구간 시작 음성과 "10초 뒤 걷기"가 화면을 끈 채로도 제때 들리는가
- 발걸음 박자: 박자가 고르게 들리는가(반복되는 이음매에서 튀지 않는가), 화면을 꺼도 계속 울리는가, 5분 안내가 나올 때 박자가 끊기지 않는가
- 페이스메이커: 실제로 빨리 · 천천히 뛰었을 때 안내가 맞게 나오고 30초 안에 되풀이되지 않는가
- 음악을 틀어 둔 채: 안내하는 동안만 볼륨이 낮아졌다가 돌아오는가(발걸음 박자 모드에서는 낮아지지 않는 것이 맞다)

## 결과 (AI 작성 — 구현 후)
- 바뀐 파일 (모두 `app/src/` 아래)
  - 계산(순수 함수): `domain/interval.ts`(인터벌 일정 · 지금 구간 찾기), `domain/modeCues.ts`(모드별 안내 · 인터벌 구간 기록), `domain/pace.ts`(최근 페이스), `domain/runView.ts`(레인 · 게이지에 그릴 값), `domain/runEngine.ts`(모드 안내를 부르는 자리, 모드별 메모)
  - 기기 기능: `services/metronome.ts`(박자 소리), `services/audioPlayers.ts`(소리 재생기 정리), `services/sounds.ts`(소리 파일 목록), `services/runController.ts`(박자 켜고 끄기), `services/voice.ts`
  - 화면 부품: `components/run/Lane.tsx`, `PaceGauge.tsx`, `RunDashboard.tsx`
  - 테스트: `domain/modeCues.test.ts`(39개), `services/sound.test.ts`(22개 — 박자 소리 · 재생기 정리 · 음성과 음악 볼륨), `services/runController.test.ts`의 "발걸음 박자" 묶음(7개)
- 실제 구조
  - 안내는 전부 순수 함수가 만든다. `runEngine.tick()`이 "지금 시각"으로 `modeCues()`를 부르고, 받은 안내 가운데 아직 말하지 않은 것(이름표가 처음인 것)만 내보낸다. 그래서 타이머가 여러 번 불려도 한 번만 말하고, 늦게 불리면 지금 구간의 안내만 말한다(D-005).
  - 인터벌 일정은 저장하지 않고 "경과 시간 → 지금 몇 번째 구간, 남은 시간"을 매번 계산한다. 일시정지한 시간은 경과 시간에 들어가지 않으므로 구간도 그만큼 멈춘다.
  - 박자 소리는 한 박자 길이의 소리 파일을 오디오 쪽에서 반복시킨다. JS 타이머로 박자를 맞추면 화면이 꺼졌을 때 밀린다. 파일은 `app/scripts/make_audio.py`가 만든다.
  - 페이스메이커의 "지금 페이스"는 최근 30초 동안의 표본으로 구하고, 표본이 20초 넘게 쌓여야 낸다(그 전에는 "페이스를 재는 중").
  - 화면 부품(레인 · 게이지)은 `describeRun()`이 준 값(구간 목록 · 진행률 · 차이 초 · 글자)을 그리기만 한다.
  - 소리 재생기는 끌 때 바로 놓아 준다. 라이브러리의 `remove()`만으로는 재생기가 메모리에 남아, 일시정지 · 재개를 되풀이하면 쌓인다(에뮬레이터에서 확인하고 고침).
- 설계 의도와 다른 점
  - 기획에 없는 문구: 인터벌을 모두 마쳤을 때 "인터벌을 모두 마쳤어요. 수고했어요", 마지막 구간의 예고 "10초 뒤 끝나요"(기획은 다음 구간 예고만 다룬다), 목표를 채웠을 때 "목표 시간을 채웠어요" · "목표 거리를 채웠어요".
  - 페이스 안내 음성에 차이 초를 덧붙였다: "조금 천천히. 목표보다 12초 빨라요". 화면의 최근 안내 줄에는 "목표보다 12초 빨라요"만 보인다.
  - 10초 전 예고는 20초보다 짧은 구간에서는 하지 않는다(시작 안내와 겹친다). 타이머가 늦게 불려 예고할 때를 3초 넘게 지났으면 예고를 건너뛴다("10초 뒤"가 틀린 말이 된다).
  - 목표를 채운 뒤 더 뛰면: 인터벌 · 페이스메이커도 자유 러닝처럼 km 지점마다 거리 안내를 한다. 페이스메이커는 목표 거리를 채운 뒤에는 페이스를 맞추라고 하지 않는다. 채우기 전에 지나온 km 지점은 뒤늦게 말하지 않는다 → Q-009.
  - 페이스 안내의 30초 간격은 "빠름"과 "느림"을 가리지 않고 적용한다(기획은 "같은 안내"). "조금 빠르게" 직후에 "조금 천천히"가 이어지지 않게 하려는 것.
  - 박자 소리를 켜지 못하면 화면에 "박자 소리를 켜지 못했어요. 일시정지했다가 재개해 보세요"를 띄운다(기획에 없는 문구). 음성이 실패하면 따로 알리지 않는다(안내 문장은 화면에 보인다).
  - 타이머가 늦어 구간을 여러 개 한꺼번에 넘었으면, 그동안 뛴 거리는 첫 구간에 넣고 건너뛴 구간은 거리 0으로 남긴다(구간별로 나눌 근거가 없다).
  - 인터벌을 모두 마친 뒤 더 뛰면 그 뒤는 1km 구간으로 이어 기록한다.
  - 게이지: 눈금의 양 끝은 목표에서 ±60초(허용 범위 ±10초의 6배)이고 그보다 더 벗어나면 마커를 끝에 붙여 둔다. 마커 크기 · 목표 띠 너비 · 가운데 "목표" 글자 · 차이 글자("45초 빠름" / "+107초 느림")는 피그마 프레임에 페이스메이커 화면이 따로 없어 설계 문서 7장의 설명대로 만들었다(디자인은 직접 확인).
- 에뮬레이터(Android API 37)에서 확인한 것 (2026-11-23)
  - 인터벌(30초 달리기 + 30초 걷기 × 2): 구간 띠가 진행에 따라 채워지고, "달리기 0:30" → "10초 뒤 걷기" → "걷기 0:30" → … → "인터벌을 모두 마쳤어요" 순으로 최근 안내가 바뀜. 종료 뒤 DB: 구간 run · walk · run · walk(각 30초, 거리 81~93m) + 남은 km 구간 1개
  - 페이스메이커(목표 6'30"): 빨리 움직이면 마커가 오른쪽 · "45초 빠름" · 안내 "목표보다 57초 빨라요", 천천히 움직이면 마커가 왼쪽 끝 · "+107초 느림"
  - 발걸음 박자(분당 170걸음): 남은 시간 표시, 앱의 소리 재생기가 러닝 중 1개 켜짐 → 일시정지 0개 → 재개 1개 → 종료 0개
  - 확인하지 못한 것: 소리가 실제로 어떻게 들리는지(에뮬레이터를 소리 없이 띄움), 화면을 끈 채의 박자 · 안내 타이밍, 목표 범위 안일 때의 게이지 화면(테스트로만 확인)
- 확인 중 본 것: 에뮬레이터가 한동안 멈췄다 풀리면서 기기 시계가 2시간 넘게 건너뛰었고, 진행 중이던 러닝의 경과 시간도 그만큼 늘었다. 경과 시간을 시계 시각의 차이로 계산하기 때문이다(D-005 "결과로 생기는 제약"에 적음). 실제 폰에서는 뛰는 중에 시계를 손으로 바꿀 때만 생긴다.
