- [제안] [확실] `describeRun`에서 `position`은 인터벌일 때만 값이 있는데, `lane` 줄이 `config.mode === 'interval' && position`으로 두 번 확인하고 `primaryFor`의 interval 분기도 `position ?? intervalPositionAt(...)`로 다시 구한다. 같은 사실을 세 곳에서 따로 지킨다. — `domain/runView.ts`(describeRun · primaryFor) — 패킷 diff 확인 — 모드별로 값을 모은 한 갈래(예: `config.mode === 'interval'`일 때 position · lane · primary를 함께 만드는 함수)로 묶거나, `primaryFor`가 position을 필수 인자로 받게 하고 interval 분기에서만 쓰게 한다.
- [신규] [제안] [추정] `deliver()`의 `say()` try/catch가 `voice.say` 안의 `Speech.speak` try/catch와 겹친다. `say`의 나머지 부분(duck 시작 등)이 던지지 않는다면 바깥 것은 중복이다. 확인: `services/voice.ts`의 `say` 전체를 열어 `Speech.speak` 밖에서 던질 수 있는 호출이 있는지 본다. — `services/runController.ts`(deliver), `services/voice.ts`(say 일부만 diff로 봄) — 한쪽만 남기고 "왜 거기서 잡는지"를 주석 한 줄로 적는다.
- [신규] [제안] [추정] `closeOrphanRuns`는 `active_run`이 한 줄이라도 있으면 아무것도 닫지 않는다. 다른 러닝이 끝나지 않은 채 남아 있으면 그 러닝은 복구 상태가 생길 때마다 계속 남을 수 있다. 확인: `insertRun` 앞뒤에서 남은 미완료 러닝을 정리하는지(시작 경로) 연다. — `db/runsRepo.ts`(closeOrphanRuns) — diff만 확인, 시작 경로 미확인 — 필요하면 `WHERE status != 'finished' AND id != <active_run의 runId>`로 좁혀 닫는다.
- [신규] [제안] [확실] 박자 범위(150~190, 5 단위)가 `CONFIG_LIMITS.cadenceSpm`, `services/sounds.ts`의 `METRONOME_SOUNDS` 키, 파일 생성 스크립트(주석 기준) 세 곳에 따로 있다. 범위를 바꾸고 소리 목록을 안 고치면 `METRONOME_SOUNDS[target]`이 undefined가 되어 재생기 생성이 실패하고, 코드는 이를 잡아 false → 토스트로 알린다(조용히 틀리진 않음). — `domain/runConfig.ts`, `services/sounds.ts`, `services/metronome.ts` — diff 확인, 스크립트 미확인 — `sounds.ts` 위에 "CONFIG_LIMITS.cadenceSpm과 같은 범위" 주석을 두거나, 목록의 키와 범위가 맞는지 확인하는 테스트 한 줄을 둔다.
