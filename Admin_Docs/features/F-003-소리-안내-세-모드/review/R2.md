## 지적 (있을 때)
- [제안] [확실] `tick`이 모드에서 메모가 오지 않아도 매번 `{ ...next, modeMemo: { ...next.modeMemo, ...mode.memo } }`로 상태 · 메모 객체를 새로 만든다. 그래서 바뀐 것이 없는 초에도 매초 새 상태가 나온다. 지금은 화면 갱신과 저장이 어차피 매초 일어나서 실제 비용은 작다 — `domain/runEngine.ts` `tick` — b59991c의 runEngine.ts 전체와 diff를 읽음(측정은 안 함) — `if (mode.memo) next = { ...next, modeMemo: { ...next.modeMemo, ...mode.memo } };`처럼 메모가 있을 때만 새로 만든다.
- [제안] [확실] 화면이 보일 때 매초 `describeRun` → `laneFor`가 `buildIntervalSteps(config).map(...)`으로 구간 배열 두 개를 새로 만든다. `Lane`은 진행 채움이 매초 바뀌어 모든 칸을 다시 그린다. 화면에서 고를 수 있는 범위(CONFIG_LIMITS, 반복 최대 20회)에서는 최대 40칸이다. 저장 값 검사(settings.ts `INTERVAL_REPEATS_MAX` = 99)와 Lane.tsx 주석으로는 198칸까지 가능하다. 매 렌더마다 칸 198개를 비교하게 된다 — `domain/runView.ts` `laneFor`, `components/run/Lane.tsx` — diff와 b59991c의 Lane.tsx · settings.ts를 읽음(실기기 렌더 시간은 재지 않음) — (1) 구간 목록은 config에만 달려 있다. `config` 객체를 키로 한 WeakMap에 담아 같은 배열을 돌려준다. (2) 지나온 칸 · 남은 칸을 memo된 작은 부품으로 나눈다. 그러면 지금 칸만 매초 다시 그린다. 반복 99회 계획이 실제로 들어오는 F-005 때 해도 된다.
- [제안] [확실] `startMetronome`에서 `disposePlayer(player)` 뒤 `createAudioPlayer`가 오류를 던지면 `player` 변수에 이미 해제한 플레이어가 남는다. `playingSpm`도 옛값이라, 같은 박자로 다시 불러도 해제된 플레이어의 `play()`만 부르게 된다(오류는 삼켜져 박자 소리만 안 난다). 지금 호출 경로에서는 일어나지 않는다. 러닝 중에는 spm이 바뀌지 않고, 일시정지 · 종료 · `resetSession`마다 `stopMetronome`이 `player = null`로 비운다 — `services/metronome.ts` `startMetronome` — diff의 metronome.ts · runController.ts 호출부를 읽음 — 해제 직후 `player = null; playingSpm = null;`을 두고 나서 새로 만든다.
- [제안] [추정] app.json의 권한 목록은 필요한 만큼이다(위치 2개 · 포그라운드 서비스 · 위치 포그라운드 서비스 · 알림 · 진동, 백그라운드 위치 제거, 저장소 차단, expo-audio 마이크 끔). 다만 플러그인이 덧붙이는 권한이 합쳐진 실제 AndroidManifest는 레포에 없어 보지 못했다(예: expo-audio `enableBackgroundPlayback`이 넣는 미디어 재생용 포그라운드 서비스 권한) — `app/app.json` — app.json 전체만 읽음, prebuild 결과 미확인 — `npx expo prebuild` 뒤 `android/app/src/main/AndroidManifest.xml`의 uses-permission을 확인하면 [확실]이 된다. ACCESS_BACKGROUND_LOCATION · RECORD_AUDIO가 다시 끼어들지 않게 하려면 `blockedPermissions`에 함께 넣어 고정한다.
