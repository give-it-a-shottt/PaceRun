## 한눈에 보기
상태: [보완] (리뷰 전)
무엇을: 요일마다 할 운동을 정해 두는 계획 탭. 템플릿 하나를 고르면 한 번에 채워지고, 요일 하나씩 직접 넣거나 바꿀 수도 있다. 정해 둔 운동은 그 요일의 홈 "오늘의 러닝"에 그대로 나온다. 💡 비유: 학교 시간표 — 한 번 짜 두면 매주 같은 요일에 같은 수업이 온다.
왜: 뛰러 나가기 전에 "오늘 뭘 하지"를 고민하지 않게 하려고(P2). 계획이 있어야 홈에서 2탭으로 시작할 수 있다.

## 설계 의도 (AI 초안 — 사용자 위임, 확인 전)
출처: pacerun-design.md 0-4 IA(PLN_01_001~004)와 "템플릿(제안값)", 0-5 Flow D

- 이 기능이 해결하는 문제: 계획이 없으면 매번 모드와 목표값을 새로 골라야 하고, 그 번거로움이 뛰지 않는 핑계가 된다.
- 완료 기준(무엇이 되면 끝인지):
  1. 계획 탭에 이번 주가 보인다: 날짜 범위, "주 3회 · 약 60분", 월~일 일곱 줄(운동 카드 또는 "운동 추가").
  2. 계획이 하나도 없으면 빈 상태("이번 주 계획이 없어요")와 [템플릿 고르기] · [직접 추가]가 보인다.
  3. 요일을 골라 운동을 넣는다: 모드 4개 가운데 하나와 목표값을 고르고 [저장]. 있던 운동을 눌러 바꾸거나 그 요일을 비울 수 있다.
  4. 템플릿 4개(인터벌 입문 · 발걸음 박자 연습 · 페이스 유지 · 혼합, 모두 주 3회) 가운데 하나를 골라 [적용]하면 요일별 운동이 채워진다. 이미 계획이 있으면 "지금 계획을 바꿀까요?"를 먼저 묻는다.
  5. 계획은 매주 되풀이된다(요일당 운동 1개). 정한 요일의 홈 "오늘의 러닝"에 그 운동이 나온다.
  6. 그 요일에 계획대로 뛰었으면(10분 이상) 완료로 보이고, 오늘과 남은 날에는 다음 회차가 차례로 붙는다("3회차", "4회차").
  7. 온보딩에서 "템플릿으로 시작하기"를 고르면 템플릿 선택 화면으로 온다.
- 화면: `/plan`(계획 탭 — 빈 상태 포함), `/plan/templates`(템플릿 선택), 계획 위 바텀시트(운동 추가 · 바꾸기)
- API: 없음(폰 안에서만 동작)
- 데이터: plan_items(요일 · 모드 · 목표값 · 이름)를 읽고 쓴다. 테이블 변경 없음.

범위 밖(다른 기능에서)
- 계획을 서버에 올리기(계획은 폰에만 둔다 — 서버 API에 계획이 없다)
- 주마다 다른 계획, 한 요일에 운동 여러 개(기획이 "매주 반복되는 계획 1개"로 정함)

## 결과 (AI 작성 — 구현 후)
- 바뀐 파일 (모두 `app/src/` 아래)
  - 계산(순수 함수): `domain/plan.ts`(템플릿 4개 · 계획 탭에 그릴 값 · 요일 하나 넣기/비우기 · 시트 제목)
  - 저장: `db/planRepo.ts`의 `replacePlan`(계획 전체를 한 트랜잭션으로 바꿔 넣기)
  - 기기 기능: `services/planData.ts`(읽어서 계산 함수에 넘기기, 요일 하나 저장 · 비우기, 템플릿 적용)
  - 화면: `app/(tabs)/plan.tsx`(계획 탭 — 빈 상태 포함), `app/plan/templates.tsx`(템플릿 선택), `app/onboarding/goal.tsx`(템플릿을 고르면 템플릿 선택 화면으로)
  - 화면 부품: `components/plan/`(PlanSummary · PlanDayRow · PlanEmpty · PlanTemplateCard · WorkoutSheet, 훅 usePlanView)
  - 고친 공용 부품: `components/TopBar.tsx`(제목 오른쪽 아이콘 버튼 · 바탕색), `components/Screen.tsx`(바탕색), `components/run/RunSetupSheet.tsx`(모드 순서 · 설명 문구를 밖에서도 쓰게 내보냄). 값을 주지 않으면 기존 화면은 그대로다.
  - 테스트: `domain/plan.test.ts`(20개 — 템플릿 · 계획 고치기 · 계획 탭에 그릴 값)
- 실제 구조
  - 계획은 요일당 한 줄(`plan_items`, 요일이 기본키)이고 매주 되풀이된다. 고칠 때는 요일 하나만 바꾸더라도 "지금 계획을 읽어 → 새 계획을 만들고 → 전체를 지우고 다시 넣기"를 한 트랜잭션으로 한다. 줄이 최대 7개라 통째로 바꾸는 편이 단순하고, 중간에 실패하면 원래 계획이 남는다.
  - 계획 탭의 글자(날짜 범위 · 합계 · 운동 이름과 회차 · 완료/오늘 표시)는 `describePlan()`이 만든다. 화면은 받은 값을 그리기만 하고, 탭이 보일 때마다 다시 읽는다.
  - 운동을 고르는 시트는 러닝 시작 전 설정과 같은 부품(모드 카드 · 목표값 고치기)을 쓴다.
  - 홈은 따로 알릴 필요가 없다. 홈이 보일 때마다 계획을 다시 읽어 "오늘의 러닝"에 반영한다(F-004).
- 설계 의도와 다른 점
  - 운동 이름: 템플릿으로 채운 운동은 템플릿의 이름("인터벌 입문")을 쓰고, 직접 추가한 운동은 모드 이름("인터벌" · "발걸음 박자" · "페이스메이커" · "자유 러닝")을 쓴다. 이름을 직접 적는 칸은 없다(피그마에 없음). 같은 모드로 목표값만 고치면 원래 이름을 지키고, 모드를 바꾸면 새 모드의 이름이 된다.
  - 템플릿 이름 "발걸음 박자 연습"은 피그마를 따랐다(기획 문서는 "케이던스 연습"). 요일 배치(인터벌 입문 월 · 목 · 토 / 발걸음 박자 연습 월 · 수 · 토 / 페이스 유지 화 · 목 · 일 / 혼합 월 · 수 · 토)도 피그마의 미리보기대로다.
  - "페이스 유지" 템플릿의 목표 페이스는 6'30"/km로 넣었다(기획에는 "3km, 목표 ±10초"만 있고 페이스 값이 없다. 시작 전 설정의 기본값과 같다 — Q-004).
  - 있던 운동을 바꾸는 화면과 "이 요일 비우기"는 피그마에 없어, 추가 시트를 그대로 쓰되 제목을 "목요일 운동 바꾸기"로 바꾸고 [저장] 아래에 글자 버튼을 두었다.
  - 오른쪽 위 [+]는 오늘부터 찾은 첫 빈 요일에 추가한다. 빈 요일이 없으면 "모든 요일에 운동이 있어요"를 띄운다.
  - 지나간 요일에 계획대로 뛰지 않았으면 회차 없이 이름만 보여 준다(못 지킨 날을 따로 표시하지 않는다). 완료는 "그날, 그 계획의 이름으로, 10분 이상 뛴 기록이 있을 때"다 — [10분만 뛰기]로 뛴 날은 계획의 완료로 보지 않는다.
  - 합계 "약 60분"은 운동들의 예상 시간을 더한 것이다. 시간 제한 없는 자유 러닝이 섞여 있으면 합계를 알 수 없어 "주 4회"처럼 횟수만 보여 준다.
  - 목표값 영역은 피그마(값 줄 + 시간 줄)와 달리 시작 전 설정과 같은 모양(줄을 누르면 − / + 가 펼쳐짐)이다. 모드 카드의 "자유"는 앱의 기존 이름 "자유 러닝"으로 나온다. [적용] 버튼 문구는 피그마대로 "이번 주에 적용"이다.
  - 시트에서 저장 · 비우기가 실패하면 시트 위에 안내를 띄운다(앱 토스트는 시트 뒤에 가려진다). 저장 중에는 시트가 닫히지 않는다.
  - 덮어쓰기 확인 창의 설명 "지금 있는 요일별 운동이 템플릿으로 바뀌어요."는 AI가 지었다(기획에는 제목과 버튼만 있다).
- 에뮬레이터(Android API 37)에서 확인한 것 (2026-11-23)
  - 계획이 없을 때: 빈 상태 → [템플릿 고르기] → 템플릿 선택(카드 4개와 요일 미리보기) → [이번 주에 적용] → 계획 탭에 "11월 16일 – 22일 · 주 3회 · 약 60분", 월 · 목 · 토에 "인터벌 입문"(그날이 일요일이라 지나간 날은 회차 없이 이름만)
  - 일요일 "운동 추가" → 시트 "일요일에 운동 추가" → [저장] → "주 4회 · 약 80분", 일요일 줄 "발걸음 박자 1회차 · 오늘" → 홈의 오늘의 러닝이 "발걸음 박자 1회차"로 바뀜
  - 온보딩 3단계에서 템플릿을 고른 채 [시작하기] → 템플릿 선택 화면 → 적용 → 계획 탭(뒤로 가기로 온보딩에 돌아가지 않음)
  - 확인하지 못한 것: 운동 바꾸기 · 비우기, 덮어쓰기 확인 창, 저장 실패 안내, 오른쪽 위 [+], 좁은 화면
