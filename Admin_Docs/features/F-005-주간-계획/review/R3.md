## 지적 (있을 때)
- [주의] [추정] 템플릿 적용 중에 뒤로 가면 적용이 끝난 뒤 `leave()`가 한 번 더 불린다 — app/src/app/plan/templates.tsx `leave` · `apply` · `useAndroidBack(leave)` · TopBar `onBack={leave}` — 패킷 diff와 03dd1e8의 db/database.ts `withWriteTransaction`만 읽음. 실행하지 않음 — 확인 방법: 에뮬레이터에서 [이번 주에 적용]을 누르자마자 폰 뒤로 가기를 눌러 화면 이동이 한 번 더 일어나는지 본다 — 고치는 방법: 적용 중(`applyingRef.current`)에는 `leave`가 아무것도 하지 않게 하거나, 화면이 떠난 뒤에는 `apply` 끝의 `leave()`를 건너뛰는 표시(언마운트 ref)를 둔다. 실패했을 때의 토스트도 이미 떠난 화면 위에 뜨는 문제가 같이 풀린다.
- [제안] [확실] 읽기 실패에도 "계획을 저장하지 못했어요" 안내가 나온다 — templates.tsx `handleApply`의 `hasPlan()` 실패 → `fail()` → `PLAN_SAVE_ERROR` — templates.tsx 전체 확인 — 고치는 방법: 읽기 실패용 문구를 따로 두거나 "계획을 처리하지 못했어요"처럼 중립 문구로 한다.

- [제안] [추정] 읽기(`listPlanItems`)가 쓰기 줄(`withWriteTransaction`) 밖에 있어, 두 저장이 겹치면 한쪽 변경이 사라질 수 있다 — services/planData.ts `saveWorkout` · `removeWorkout` — 화면 쪽은 `busyRef` · `applyingRef`로 막혀 있어 실제 화면 조작으로 겹치기는 어렵다고 봄. 확인 방법: 두 저장 함수를 `Promise.all`로 동시에 불러 결과를 본다 — 고치는 방법: 읽기와 쓰기를 `replacePlan` 같은 하나의 `withWriteTransaction` 안에서 하게 한다.
