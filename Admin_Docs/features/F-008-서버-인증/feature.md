## 한눈에 보기

무엇을: 이메일 + 비밀번호로 가입 · 로그인하고, 로그인 상태를 토큰으로 이어 가는 서버. 💡 비유: 가입하면 회원증을 만들고, 로그인하면 30분짜리 출입증과 30일짜리 교환권을 준다.
왜: 폰의 기록을 웹에서도 보려면 "누구의 기록인지" 서버가 알아야 한다(D-002).

## 설계 의도 (AI 초안 — 사용자 위임, 확인 전)
출처: pacerun-design.md 0-4(MY_01_003 · 004, WEB_01_001), 0-5 Flow E · 동기화 규칙, D-002, D-006

- 이 기능이 해결하는 문제: 계정이 없으면 폰의 기록을 서버에 올리거나 웹에서 볼 수 없다.
- 완료 기준(무엇이 되면 끝인지):
  1. 이메일 + 비밀번호(8~72자)로 가입한다. 이미 가입된 이메일이면 409로 알려 준다(대소문자만 다른 이메일도 같은 이메일로 본다).
  2. 로그인하면 액세스 토큰(30분)과 리프레시 토큰(30일)을 받는다. 이메일이 없든 비밀번호가 틀리든 같은 401을 준다.
  3. 리프레시 토큰으로 새 토큰을 받는다. 한 번 쓴 리프레시 토큰은 다시 쓸 수 없고, 한참 전에 쓴 토큰이 다시 오면(새어 나간 것으로 보고) 그 회원의 토큰을 모두 끊는다. 방금(10초 안) 교체된 토큰이 다시 온 것은 동시 요청으로 보고 그 요청만 거절한다.
  4. 로그아웃하면 그 리프레시 토큰을 못 쓰게 한다.
  5. 액세스 토큰으로 내 정보를 읽고 주 목표(2~5)를 바꾼다. 토큰이 없거나 만료 · 변조됐으면 401.
  6. 비밀번호와 리프레시 토큰은 해시로만 저장한다.
  7. 웹은 리프레시 토큰을 자바스크립트가 읽을 수 없는 쿠키로만 받고, 앱은 응답 본문으로 받는다.
  8. 에러는 모두 `{"detail": {"code", "message"}}` 한 가지 모양이다. 서버 내부 사정(스택 · SQL)과 받은 비밀번호는 응답에 넣지 않는다.
  9. 비밀번호 찾기는 만들지 않는다(MVP 제외).
- 화면: 없음(서버). 앱 화면은 F-010, 웹 화면은 F-011.
- API: `POST /auth/signup · login · refresh · logout`, `GET · PATCH /me` (overview/api-list.md "인증")
- 데이터: users, refresh_tokens 테이블(overview/data-model.md "서버")

## 결과 (AI 작성 — 구현 후)
- 바뀐 파일
  - 구성: `docker-compose.yml`(개발용 Postgres 16), `.env.example`, `server/.env.example`, `server/pyproject.toml`, `server/alembic.ini`
  - 앱 조립 · 공통: `server/app/main.py`(CORS · 라우터), `config.py`(환경변수), `db.py`(연결 · 세션), `errors.py`(에러 형식), `security.py`(해시 · 토큰), `deps.py`(로그인 확인)
  - 모델: `server/app/models/user.py`, `refresh_token.py`
  - 스키마(요청 · 응답 모양): `server/app/schemas/auth.py`
  - 서비스: `server/app/services/auth_service.py`
  - 라우터: `server/app/routers/auth.py`, `me.py`
  - 마이그레이션: `server/alembic/env.py`, `versions/0001_users_and_refresh_tokens.py`
  - 테스트: `server/tests/conftest.py`, `test_auth.py`
- 실제 구조
  - 라우터 → 서비스 → 모델 순으로만 의존한다. 서비스는 요청 · 응답 · 쿠키를 모르고, 실패는 `AppError(상태 코드, 코드, 문구)`로 던진다. 라우터는 응답 모양과 쿠키만 맡는다.
  - 리프레시 토큰은 무작위 문자열이고 DB에는 SHA-256 해시만 둔다. 갱신할 때 그 줄을 잠가(FOR UPDATE) 같은 토큰으로 동시에 두 번 갱신하지 못하게 한다.
  - 교체된 토큰이 다시 오면: 10초 안이면 동시 요청으로 보고 401만, 10초가 넘었으면 새어 나간 것으로 보고 그 회원의 토큰을 모두 끊는다. 로그아웃은 토큰 줄을 지운다. 토큰을 새로 줄 때 만료됐거나 교체된 지 하루 넘은 줄을 함께 지운다.
  - 웹은 `X-Refresh-Mode: cookie` 헤더를 보낸다. 그러면 응답 본문의 `refresh_token`은 null이고 `pr_refresh` 쿠키(httpOnly · SameSite=Lax · 경로 `/api/v1/auth`)로만 간다.
  - 가입하지 않은 이메일로 로그인해도 가짜 해시로 검증을 한 번 돌려, 응답 시간으로 가입 여부를 알 수 없게 했다.
  - 테스트는 별도 DB(`…_test`)에 Alembic으로 테이블을 만들고, 테스트마다 트랜잭션을 되돌린다.
- 설계 의도와 다른 점
  - 처음 API 목록에는 `TokenOut.refresh_token`이 항상 문자열이었다. 웹에서 응답 본문으로도 토큰이 가면 쿠키로 숨기는 뜻이 없어져서, 쿠키 방식에서는 null로 바꾸고 `X-Refresh-Mode` 헤더를 추가했다(api-list.md 반영).
  - 로그인 시도 횟수 제한은 넣지 않았다(1인 사용 · 배포 전). 배포할 때 필요하다 → Q-002.
