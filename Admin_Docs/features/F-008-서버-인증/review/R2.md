## 지적 (있을 때)
- [주의] [추정] 같은 리프레시 토큰으로 갱신 요청 두 개가 동시에 오면(웹 탭 여러 개, 앱 재시도) 정상 사용자가 모든 기기에서 로그아웃된다. 코드 주석은 "한 요청만 성공"이라고 하지만, 실제로는 A가 잠금을 잡고 revoked_at을 채워 커밋한 뒤, 기다리던 B의 `SELECT … FOR UPDATE`가 Postgres READ COMMITTED 규칙대로 바뀐 줄(revoked_at 있음)을 다시 읽는다. 그러면 B가 재사용으로 판정해 `_revoke_all`을 부르고, A가 방금 내준 새 토큰까지 끊긴다. 안전한 쪽으로 실패하므로 보안 구멍은 아니지만, 재사용 감지가 정상 사용자를 공격자로 오판한다 — `server/app/services/auth_service.py` `refresh()` — diff에서 잠금 · 재사용 분기를 읽었고 실행은 안 함(패킷: 동시 갱신 테스트 없음) — 스레드 두 개(또는 DB 세션 두 개)로 같은 토큰을 동시에 갱신하는 테스트를 돌려 A의 새 토큰이 끊기는지 보면 [확실]이 된다. 고치는 방법: (1) F-010 · F-011 클라이언트가 갱신을 한 번에 하나만 보내게 하고(single-flight), (2) 서버에서는 "교체로 끊긴 지 몇 초 안 된 토큰"이면 `_revoke_all` 없이 401만 주는 짧은 유예를 두거나, 끊긴 이유(교체 / 로그아웃)를 칸 하나에 남겨 구분한다.
- [제안] [추정] 개발용 의존성 `httpx2`는 잘 알려진 `httpx`와 이름이 거의 같다. 잠금 파일에는 PyPI 출처로 2.16.2가 잡혀 있고 `httpx`는 아예 없다(TestClient가 이 패키지로 동작) — `server/pyproject.toml` `[dependency-groups].dev`, `server/uv.lock` — pyproject와 uv.lock(b5837b7)의 패키지 항목만 확인했고, 이 패키지가 Starlette 1.10 TestClient가 공식으로 지원하는 패키지인지는 확인하지 못함 — Starlette 1.10 문서나 변경 기록에서 TestClient가 `httpx2`를 쓰는지, PyPI의 `httpx2` 관리자가 encode/httpx 쪽인지 보면 [확실]이 된다. 공식이 아니면 공식 패키지로 바꾼다.
- [제안] [확실] `refresh_tokens`에 쌓인 줄이 지워지지 않는다. 로그인 · 갱신 때마다 한 줄씩 늘어나고(사용 중이면 30분마다), 끊긴 토큰과 만료된 토큰 모두 영원히 남는다. 지금은 1인 사용이라 문제가 없다 — `server/app/services/auth_service.py` `_issue_tokens()`, `server/app/models/refresh_token.py` — diff 전체에서 DELETE가 없음을 확인함 — 만료(expires_at)가 지난 줄을 지우는 정리 작업(관리 명령이나 로그인 시 그 회원 것만 정리)을 둔다. 재사용 감지에는 끊긴 줄이 필요하니 만료 전 줄은 남긴다.
