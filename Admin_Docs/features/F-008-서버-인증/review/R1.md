## 지적 (있을 때)
- [신규] [주의] [확실] `RefreshToken.revoked_at` 주석이 "쓰였거나(교체) 로그아웃된 시각"이라고 적혀 있는데, 로그아웃은 `revoked_at`을 채우지 않고 줄을 지운다. data-model.md(교체된 시각)와도 어긋나서 읽는 사람이 로그아웃 토큰이 남아 있다고 오해한다 — server/app/models/refresh_token.py(RefreshToken.revoked_at) ↔ server/app/services/auth_service.py(logout) — 두 파일 전체와 data-model.md 서버 표를 직접 읽음 — 주석을 "교체됐거나 회원 전체 폐기(_revoke_all)된 시각. 로그아웃은 줄을 지운다"로 고친다.
- [신규] [제안] [확실] 회원 정보 수정(`update_weekly_goal`)이 `auth_service`에 들어 있다. 이름은 인증인데 하는 일은 프로필 수정이라, `me.py`가 auth_service에 의존한다. 지금은 함수 하나라 문제는 아니지만 프로필 기능이 늘면 위치가 모호해진다 — server/app/services/auth_service.py(update_weekly_goal), server/app/routers/me.py — 두 파일 전체를 직접 읽음 — 늘어나는 시점에 `user_service.py`로 분리하거나, 당분간 두려면 모듈 docstring에 "내 정보 수정 포함"을 적는다.
- [신규] [제안] [확실] 리프레시 쿠키 삭제 호출 `delete_cookie(REFRESH_COOKIE, path=REFRESH_COOKIE_PATH)`가 `refresh`(실패 시)와 `logout` 두 곳에 같은 인자로 반복된다. 또 토큰을 어느 쪽에서 읽는지 규칙이 다르다(refresh는 mode로 쿠키/본문 택일, logout은 `cookie_token or body`). refresh 쪽만 이유 주석이 있고 logout은 없다 — server/app/routers/auth.py(refresh, logout) — 파일 전체를 직접 읽음 — `_clear_refresh_cookie(response)` 헬퍼로 묶고, logout의 우선순위 이유(쿠키 우선)를 한 줄 주석으로 남긴다.
- [신규] [제안] [확실] 값이 다른 파일과 맞아야 하는 숫자가 이름 없이 흩어져 있다. 해시 길이 64(`String(64)`가 모델·마이그레이션에, SHA-256 hexdigest 길이라는 근거는 문서에만), `RefreshIn.refresh_token`의 `max_length=512`(`token_urlsafe(48)`이 만드는 길이 약 64와의 관계 설명 없음), `token_urlsafe(48)`·`token_urlsafe(16)` — server/app/models/refresh_token.py, server/app/schemas/auth.py(RefreshIn), server/app/security.py — 세 파일 전체를 직접 읽음 — 모델에 "SHA-256 hex = 64자" 주석, 스키마에 "토큰 길이보다 넉넉한 상한" 주석을 한 줄씩 단다(상수로 뽑을 필요까지는 없음).
- [신규] [제안] [확실] pyproject.toml에서 `# S101: 테스트의 assert / S105·S106: 테스트용 가짜 비밀번호` 주석이 `[tool.ruff.lint]`의 select 바로 아래에 떠 있고, 설명 대상인 `per-file-ignores`는 그 아래 다른 섹션에 있다. 읽을 때 select 설명처럼 보인다 — server/pyproject.toml — 파일 전체를 직접 읽음 — 주석을 `[tool.ruff.lint.per-file-ignores]` 바로 위로 옮긴다.
