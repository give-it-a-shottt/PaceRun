## 지적 (있을 때)
- [신규] [제안] [확실] api-list.md "인증"의 재사용 규칙에 보존 기한이 빠져 있다. 문서는 "교체된 지 10초가 넘은 토큰이 다시 오면 그 회원의 토큰을 모두 폐기"라고만 적었는데, 서버는 교체된 지 하루가 넘은 줄을 토큰을 새로 줄 때 지운다. 그 뒤에 그 토큰이 오면 줄이 없어(`stored is None`) 전체 폐기 없이 401 `INVALID_REFRESH`만 나간다 — 위치: auth_service.refresh · _delete_stale_tokens(문서는 data-model.md refresh_tokens 칸에만 하루 보존이 있음) — 확인한 범위: auth_service.py 전체, api-list.md · data-model.md 해당 절 — 고치는 방법: api-list.md 재사용 항목에 "교체 후 하루가 지난 토큰은 줄이 지워져 단순 401" 한 줄 추가(코드는 그대로 둬도 설계상 문제 없음).
- [신규] [제안] [확실] api-list.md가 로그인 · /me의 입력 오류를 빠짐없이 적지 않았다. LoginIn은 비밀번호 73자 이상이면 401이 아니라 422 `VALIDATION`이고, PATCH /me는 weekly_goal이 2~5 밖이면 422인데 /me 두 줄의 "에러" 칸은 비어 있다(공통 에러의 422로 읽을 수는 있음). 쿠키의 `Secure` 속성(설정 `cookie_secure`, 기본 false)도 문서에 없다 — 위치: schemas/auth.py(LoginIn · MeUpdateIn), routers/auth.py `_deliver` — 확인한 범위: 해당 파일 전체와 api-list.md 인증 절 — 고치는 방법: /me 에러 칸에 "401 UNAUTHORIZED, (PATCH) 422 VALIDATION"을 적고, 쿠키 설명에 "배포(HTTPS) 때는 Secure를 켠다(설정 cookie_secure)"를 덧붙인다.
- [신규] [제안] [추정] 공통 에러 형식의 `message`는 "사용자에게 보여 줄 말"인데, 404 · 405 등 프레임워크가 만든 HTTP 오류는 `error.detail`을 그대로 쓴다(handle_http). Starlette 기본 문구라면 영어("Not Found")가 나올 수 있다 — 위치: errors.py handle_http — 확인한 범위: errors.py 코드만 읽음, 실제 응답은 실행하지 않음 — [확실]이 되려면 존재하지 않는 경로로 curl을 보내 message를 확인한다 — 고치는 방법: 404 · 405 · 403 문구를 한국어로 고정하거나, 문서에 "이 코드들의 message는 고정 한글이 아닐 수 있다"고 적는다.
