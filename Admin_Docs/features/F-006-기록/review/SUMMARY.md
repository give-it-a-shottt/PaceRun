## 최종 판정 (AI 위임 판정 — 사용자 확인 전)
- 수용할 지적과 이유: 아래 둘을 뺀 전부.
  - 빈 상태의 [10분만 뛰기]: 두 회차에 걸쳐 두 리뷰어가 지적했고 완료 기준과 어긋난다는 말이 맞아 1차의 거절을 뒤집었다. 누르면 끝나지 않은 러닝이 있는지 먼저 보고, 있으면 시작하지 않고 홈으로 보낸다(홈이 "이어서 / 여기까지 저장"을 묻는다). 확인하지 못하면 그대로 시작한다 — 시작하는 쪽이 한 번 더 막는다.
  - 읽기 훅: 결과에 "어느 요청의 결과인지"를 함께 적어 두고, 지금 요청의 결과가 아니면 읽는 중으로 본다.
  - 읽기 실패 테스트를 완료 요약 · 기록 탭에도 붙였다(`recordsData.test.ts` 10개).
  - 지표 함수의 인자를 이름 있는 값(`withPaceUnit`)으로, 구간 종류 글자는 작은 함수로 뺐다.
- 거절할 지적과 이유:
  - 읽기 훅의 테스트: 화면 훅을 테스트에서 띄우는 도구가 없다(D-001). 대신 에뮬레이터에서 상세 열기 · 없는 번호 · 뒤로 가기를 다시 확인했다.
  - 목표값 칸이 깨진 러닝: 그 칸을 쓰는 곳은 앱 자신뿐이고 확인된 값만 적는다(러닝을 시작할 때, 그리고 F-010에서 서버 기록을 내려받을 때). 깨질 길이 보이면 그때 읽는 쪽을 고친다.
- 다음에 고칠 것: Q-011 · Q-012의 답에 따라 목표선과 비교 기준을 맞춘다.
