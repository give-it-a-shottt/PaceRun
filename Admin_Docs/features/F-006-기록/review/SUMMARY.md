## 최종 판정 (AI 위임 판정 — 사용자 확인 전)
- 수용할 지적과 이유: 아래 둘을 뺀 전부.
  - 완료 요약도 끝난 러닝만 그리게 했다(상세와 같은 함수로 확인). 끝나지 않은 러닝의 번호로 열면 "기록을 찾지 못했어요"가 나온다.
  - 읽기 상태 관리를 공용 훅(`useLoadedValue`) 하나로 모아 두 화면이 함께 쓴다.
  - 막대 눈금의 바닥값에 이름을 붙이고(100m) 죽은 코드와 틀린 주석을 고쳤다.
  - 완료 요약의 값에서 `counted` · "오늘 1회 인정!"을 빼고 상세와 같은 `note`(10분 미만일 때만 한 줄) 하나로 줄였다.
  - `recordsData`에 테스트 8개를 붙였다(끝난 러닝 · 없는 번호 · 끝나지 않은 러닝 · 읽기 실패 · 빈 상태).
  - feature.md에 세 기준과 빈 상태 [10분만 뛰기]의 동작을 적었다.
- 거절할 지적과 이유:
  - 빈 상태의 [10분만 뛰기]에 미완료 러닝 확인 넣기: 앱을 켜면 홈이 먼저 뜨고 거기서 복구 창이 닫히지 않는 한 다른 탭으로 갈 수 없다. 그래도 남은 경우에는 시작이 막히고("이미 기록 중인 러닝이 있어요") 홈으로 보내 복구 창을 띄운다 — 기록이 망가지지 않는다. 복구 창을 기록 탭에도 띄우려면 홈의 복구 흐름을 탭 바깥으로 옮겨야 해서 얻는 것에 비해 크다.
  - 지표를 줄로 나누는 반복문: "한 줄에 몇 칸"은 화면의 배치이고 두 화면의 배치가 실제로 다르다(상세 2칸, 요약 3칸).
  - 기록 탭 "가장 최근 요청만 받기"의 테스트: 화면 훅을 테스트에서 띄우는 도구가 없다(D-001). 홈 · 계획과 같은 번호 비교 한 줄이다.
