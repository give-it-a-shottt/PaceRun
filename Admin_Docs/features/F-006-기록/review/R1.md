## 지적 (있을 때)
- [제안] [확실] 막대 기준값 계산의 `|| KM`은 죽은 코드이고, 위 주석("모두 0이면 1km를 기준으로 둔다")이 실제 동작(바닥값 0.1km)과 다르다. `Math.max(..., KM / 10)`이 항상 0보다 커서 `|| KM`은 실행되지 않는다. `KM / 10`도 이름 없는 숫자다 — domain/records.ts `describeRecords`의 `scaleM` — 패킷 diff의 해당 줄과 주석을 직접 읽음 — `|| KM`을 지우고 `const MIN_CHART_SCALE_M = 100`처럼 이름을 붙인 뒤 주석을 "아무리 짧아도 막대 기준은 100m"로 고친다.
- [제안] [확실] 읽기 상태 관리(loading/ready/missing/failed 상태 + cancelled 플래그 + attempt로 다시 읽기)가 러닝 상세와 완료 요약 두 화면에 거의 같은 모양으로 들어 있다 — app/records/[id].tsx · app/run/summary/[id].tsx — 두 파일의 diff를 직접 읽음 — 화면이 둘뿐이라 급하지 않다. 세 번째 화면이 생기면 `useLoadedView(load, deps)` 같은 훅으로 뽑는다.
- [제안] [확실] 지표를 두 칸씩 줄로 나누는 반복문(`statRows`)이 러닝 상세 화면 파일 안에 있다. 값 계산은 아니고 배치 규칙이라 domain 대상은 아니나, 완료 요약(RunSummaryView)도 지표 3개를 그리는 비슷한 부분이 있어 배치 규칙이 두 곳에 갈릴 수 있다 — app/records/[id].tsx `RunDetail` — 상세는 diff로 읽었고 RunSummaryView는 `grep`으로 Stat 사용 줄만 봄 — 같은 지표 줄 배치를 쓰는 부품(예: `StatGrid`)이 필요해질 때 함께 뺀다.
- [제안] [추정] `loadSummaryView`는 러닝이 끝났는지(`status === 'finished'`)를 확인하지 않는데 `loadRunDetailView`는 확인한다. 두 읽기 함수의 기준이 다르다 — services/recordsData.ts — diff만 읽음. 완료 요약 화면은 러닝 종료 뒤에만 열리는 흐름인지 runController 쪽을 열어 봐야 [확실]이 된다 — 의도한 차이면 한 줄 주석으로 이유를 남기고, 아니면 같은 조건을 쓴다.
- [제안] [확실] `SummaryView`에 `counted`와 `week.paintKey`가 겹친다(`paintKey`는 `counted`일 때만 값이 있다) — domain/records.ts `describeSummary` — diff를 직접 읽음 — 화면이 `counted`를 따로 쓰는지(RunSummaryView 미열람) 확인해 쓰지 않으면 `counted`를 지운다.
