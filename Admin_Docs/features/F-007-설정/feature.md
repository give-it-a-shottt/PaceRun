## 설계 의도 (AI 초안 — 사용자 위임, 확인 전)
출처: pacerun-design.md 0-4 IA(MY_01_001), 6장 사용자 결정 3(러닝 화면 테마), 7장 "테마 적용 범위"

- 이 기능이 해결하는 문제: 처음 정한 값이 맞지 않게 됐을 때(목표가 버겁다, 알림 시간이 안 맞는다, 밤에 화면이 눈부시다) 고칠 수 없으면 앱을 그만 쓰게 된다.
- 완료 기준(무엇이 되면 끝인지):
  1. "내 정보" 탭에 설정이 묶음별로 보이고 줄마다 지금 값이 적혀 있다: 러닝 목표(주 목표 · 알림 시간) / 음성 안내(음성 안내 · 안내 간격 · 기본 발걸음 박자) / 화면(러닝 화면 테마) / 기록(배터리 최적화 확인).
  2. 주 목표를 2~5회 가운데 고르면 홈의 "이번 주 N / M회"가 따라 바뀐다.
  3. 알림 시간을 켜고 끄고 시각을 고치면 매일 알림 예약이 따라 바뀐다. 알림을 켜 두었는데 폰의 알림 권한이 꺼져 있으면 그 사실과 [설정 열기]를 보여 준다.
  4. 음성 안내를 끄면 러닝 중에 말하지 않는다. 안내 간격은 자유 러닝에서 거리 · 페이스를 말해 주는 간격이다.
  5. 기본 발걸음 박자를 고치면 발걸음 박자 모드를 처음 고를 때의 값이 된다.
  6. 러닝 화면 테마를 "자동(OS 설정 따름)"과 "항상 밝게" 가운데 고른다.
  7. 바꾸면 바로 저장된다. 저장에 실패하면 원래 값으로 되돌리고 알린다.
- 화면: `/my`(내 정보 탭). 값을 고치는 바텀시트 5개.
- API: 없음(폰 안에서만 동작. 주 목표를 서버에 올리는 것은 F-010)
- 데이터: settings 테이블의 weeklyGoal · reminderTime · voiceEnabled · voiceIntervalKm · defaultCadenceSpm · runTheme를 읽고 쓴다. 테이블 변경 없음.

범위 밖(다른 기능에서)

- 설정을 서버에 올리기 · 내려받기(주 목표만 F-010에서 올린다)

## 결과 (AI 작성 — 구현 후)
- 바뀐 파일 (모두 `app/src/` 아래)
  - 계산(순수 함수): `domain/settingsView.ts`(줄마다 보여 줄 글자 `describeSettings`, 고를 수 있는 값의 목록, 발걸음 박자 한 칸 올리고 내리기, 알림 시간 값 바꾸기, 알림 권한 안내)
  - 기기 기능: `services/permissions.ts`의 `getNotificationAccess`(묻지 않고 알림 권한만 확인)
  - 화면: `app/(tabs)/my.tsx`
  - 화면 부품: `components/settings/`(ListRow · SettingsSection · SettingsSheet · ChoiceList · StepField · ReminderFields · ReminderNotice, 시트 5개 WeeklyGoalSheet · ReminderSheet · VoiceIntervalSheet · CadenceSheet · RunThemeSheet, 훅 useSettingsView)
  - 옮긴 부품: `Toggle`은 `components/` 바로 아래로, `WeeklyGoalPicker`는 `components/settings/`로(온보딩과 설정이 함께 쓴다). 온보딩의 `ReminderTimePicker`는 줄과 펼침만 남기고 펼친 칸은 `settings/ReminderFields`를 쓴다. `app/onboarding/goal.tsx`는 가져오는 경로와 알림 값 바꾸는 함수만 바뀌었다.
  - 지운 것: `components/ComingSoon.tsx`("준비 중" 화면 — 쓰는 탭이 없어졌다)
  - 테스트: `domain/settingsView.test.ts`(14개 — 줄의 글자 · 알림 권한 안내 · 알림 시간 값 바꾸기 · 발걸음 박자 올리고 내리기 · 고를 수 있는 값의 목록)
- 실제 구조
  - 화면은 값을 계산하지 않는다. `useSettingsView`가 설정(store)과 폰의 알림 권한을 읽어 `describeSettings()`에 넘기고, 화면은 받은 글자를 그린다.
  - 저장은 F-001의 설정 store(`update(key, value)`)를 그대로 쓴다: 화면 값을 먼저 바꾸고 DB에 저장하고, 실패하면 그 값만 되돌리고 토스트로 알린다.
  - 알림 예약은 이 화면이 직접 하지 않는다. 알림 시간이 바뀌면 루트 레이아웃이 알아서 다시 예약한다(F-004).
  - 알림 권한은 화면이 보일 때 · 앱으로 돌아올 때 다시 확인한다(폰 설정에서 권한을 켜고 돌아오면 안내가 사라진다).
- 설계 의도와 다른 점
  - 값을 고치는 화면은 피그마에 없다(줄만 있다). 줄을 누르면 바텀시트가 열리게 만들었다(AI 위임 결정). 주 목표 · 안내 간격 · 러닝 화면 테마는 고르면 저장하고 시트가 닫힌다. 알림 시간 · 기본 발걸음 박자는 누를 때마다 저장하고 [완료]는 닫기만 한다.
  - 안내 간격으로 고를 수 있는 값은 1 · 2 · 3 · 5km다(기획에는 "간격"만 있다) → Q-004.
  - 기본 발걸음 박자의 범위는 시작 전 설정과 같다(분당 150~190걸음, 5씩 — 박자 소리 파일이 있는 범위).
  - 알림을 끈 상태에서 켜면 알림 권한 창을 띄운다(이미 허용했으면 뜨지 않는다). 거부해도 켠 채로 저장하고, 줄 아래에 "알림 권한이 꺼져 있어 알림이 오지 않아요"와 [설정 열기]를 보여 준다(피그마에 없음. F-004 리뷰에서 넘어온 것).
  - 음성 안내를 꺼도 "안내 간격" 줄은 그대로 고칠 수 있다(막지 않았다).
  - 러닝 화면 테마의 설명 줄("폰이 다크 모드면 러닝 화면도 어둡게 보여요" / "폰이 다크 모드여도 러닝 화면은 밝게 보여요"), [완료], 시트 안의 "발걸음 박자"는 AI가 지은 문구다.
  - 상단 제목 "내 정보"는 다른 탭과 같은 크기(20)다. 피그마의 이 화면은 18이다(계획 · 기록 탭도 같은 차이).
- 에뮬레이터(Android API 37)에서 확인한 것 (2026-11-23)
  - 내 정보 탭에 묶음 4개와 줄마다 지금 값이 보임
  - 주 목표 2회 → 3회: 줄이 "3회"로, 홈이 "이번 주 0 / 3회"로 바뀜
  - 안내 간격 1km → 2km, 기본 발걸음 박자 170 → 180([+] 두 번 → [완료]), 러닝 화면 테마 → 항상 밝게: 줄의 값이 바뀌고 앱을 다시 켜도 남아 있음
  - 알림 시간 7:00 → 7:10: 줄이 "매일 오전 7:10"으로, 폰의 알림 예약이 07:10으로 바뀜
  - 알림 권한을 끄면 줄 아래에 안내와 [설정 열기]가 뜨고, 권한을 다시 켜고 앱으로 돌아오면 사라짐
  - 음성 안내 토글 끄기 · 켜기, [배터리 최적화 확인] → 폰의 설정 화면이 열림
- 확인하지 못한 것: 알림을 끈 상태에서 켤 때 권한 창이 뜨는 흐름(에뮬레이터에서는 권한을 명령으로 바꿨다), 고친 시각에 알림이 실제로 오는지, 저장 실패 안내, 음성 안내를 끄고 뛰었을 때 말하지 않는지(F-003의 테스트로만 확인), 온보딩 3단계가 부품을 옮긴 뒤에도 그대로인지(코드로만 확인)
