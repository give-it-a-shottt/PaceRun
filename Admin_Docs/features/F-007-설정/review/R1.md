## 지적 (있을 때)
- [제안] [확실] 알림 시간 줄의 글자("매일 오전 7:00" / "끔")를 만드는 코드가 두 곳에 있다. `describeSettings`(domain/settingsView.ts)는 `REMINDER_OFF_TEXT`를 쓰는데, 온보딩의 `ReminderTimePicker`는 `` `매일 ${formatReminderClock(...)}` ``와 `'끔'`을 따로 적는다. 문구를 바꾸면 한쪽만 바뀔 수 있고, `REMINDER_OFF_TEXT`는 export만 되고 domain 밖에서는 안 쓰인다 — components/onboarding/ReminderTimePicker.tsx, domain/settingsView.ts — 두 파일 전체를 읽었다 — domain에 `reminderChoiceText(choice)` 같은 함수를 두고 `describeSettings`와 `ReminderTimePicker`가 함께 쓰게 한다.
- [제안] [확실] 온보딩 컴포넌트가 설정 폴더의 부품을 가져다 쓴다(`onboarding/goal.tsx` → `settings/WeeklyGoalPicker`, `onboarding/ReminderTimePicker` → `settings/ReminderFields`). architecture.md는 "여러 화면이 함께 쓰는 부품은 components/, 한 기능에서만 쓰는 부품은 기능 폴더"라고 한다. 두 기능이 함께 쓰는 부품이 기능 폴더 한쪽에 있는 모양이다 — 패킷 diff와 ReminderTimePicker 전체, architecture.md 해당 줄 — 의존 방향이 한쪽(온보딩 → 설정)이라 지금 문제는 없다. 부품이 늘면 `components/` 바로 아래(또는 공용 폴더)로 옮기는 것을 고려한다.
- [제안] [확실] `CadenceSheet`는 값을 store에서 직접 읽으면서(`spm`), 글자(`valueText`)만 화면(`my.tsx`)에서 prop으로 받는다. 같은 값의 출처가 둘로 나뉘어 있다. 다른 시트는 글자를 prop으로 받지 않는다 — components/settings/CadenceSheet.tsx, app/(tabs)/my.tsx — 두 파일 전체를 읽었다 — `cadenceText(nearestCadence(spm))`를 시트 안에서 만들면 prop이 없어지고 다른 시트와 모양이 같아진다.
