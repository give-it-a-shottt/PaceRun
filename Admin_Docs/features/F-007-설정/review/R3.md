## 지적 (있을 때)
- [제안] [추정] 설정을 DB에서 읽지 못했을 때(`status: 'failed'`) 내 정보 화면이 기본값을 실제 값처럼 그린다 — `app/(tabs)/my.tsx`, `useSettingsView.ts`(`settings`만 읽고 `status`는 보지 않음) — 패킷 diff와 `settingsStore.ts`만 확인, 루트 레이아웃 등 다른 곳에서 읽기 실패를 따로 알리는지는 열지 않음 — 루트 레이아웃이 읽기 실패를 이미 막거나 안내하는지 확인해 보고, 없으면 `status === 'failed'`일 때 안내(또는 값 대신 "불러오지 못했어요")를 처리한다. 이미 막혀 있으면 지적을 취소한다.
- [제안] [확실] `getNotificationAccess`(권한 확인이 던지면 'unknown'으로 바꾸는 예외 처리)와 `useSettingsView`의 "가장 최근 확인만 받기"에 자동 테스트가 없다 — `services/permissions.ts`, `components/settings/useSettingsView.ts` — 패킷 테스트 목록과 `settingsView.test.ts` 확인. 화면 테스트 도구를 들이지 않는 결정(D-001)과 맞물려 있음 — `Notifications`를 모의(mock)로 바꿔 `getNotificationAccess`의 granted / denied / 던짐 → unknown 3가지만 서비스 테스트로 추가하면 된다(선택).
