## 지적 (있을 때)
- [신규] [제안] [확실] 에러 응답 모양 `{"detail": {"code", "message"}}`을 만드는 코드가 두 곳이다. `middleware.py`의 `_error`와 `errors.py`의 `_body`. 에러 형식을 바꾸면 한쪽만 고치기 쉽다 — server/app/middleware.py `_error`, server/app/errors.py `_body` — 패킷 diff와 errors.py 앞부분(1~40줄)을 직접 읽음. errors.py의 핸들러 전체는 안 읽음 — errors.py에 공개 헬퍼(예: `error_response(status, code, message)`)를 두고 미들웨어가 그걸 쓰게 한다. 미들웨어가 errors를 import해도 순환은 없다.
- [신규] [제안] [확실] "월/년" 기간 타입이 두 곳에 따로 있다. 서비스는 `Period = Literal["month", "year"]`, 응답 스키마 `StatsOut.period`는 같은 리터럴을 다시 적었다. 기간이 늘면 한쪽을 빠뜨린다 — server/app/schemas/stats.py `StatsOut.period`, server/app/services/stats_service.py `Period` — diff에서 두 파일 전체를 읽음 — 한 곳(스키마 쪽이 계약이므로 schemas)에 정의하고 서비스가 import하거나, 스키마가 서비스의 `Period`를 import한다.
- [신규] [제안] [확실] frozen dataclass `_Scope`에서 `local_day`를 `field(init=False)` + `__post_init__`의 `object.__setattr__`로 채운다. 읽는 사람이 한 번 멈칫하는 우회다 — server/app/services/stats_service.py `_Scope` — diff 전체를 읽음 — `local_day`를 `@property`(또는 `functools.cached_property` 대신 단순 property, 쿼리 식 생성 비용이 작음)로 바꾸면 우회가 필요 없다.
- [신규] [제안] [확실] 10분 인정 상수 `COUNTED_MIN_ELAPSED_S`가 모델 파일(`models/run.py`)에 있고, 서비스는 `app.models`가 아닌 `app.models.run`에서 따로 import한다. 이 상수는 모델의 칸이 아니라 "인정 규칙"이라 서비스 쪽에 두는 게 역할에 맞다 — server/app/models/run.py, server/app/services/run_service.py import부 — diff에서 두 파일을 읽음. 사용처가 run_service 한 곳인지는 stats_service/테스트를 전부 확인하지 않음 — 서비스 모듈 상단으로 옮기고 위 "앱과 서버에 규칙이 따로 있다(D-003)" 주석도 함께 옮긴다.
