## 최종 판정 (AI 위임 판정 — 사용자 확인 전)
- 수용할 지적과 이유: [주의] 3개 전부와 [제안] 가운데 아래 하나를 뺀 전부.
  - 크기 상한: 1차에서 넣은 방어가 한 줄짜리 머리글로 뚫리면 넣은 의미가 없다. 테스트 11개(`test_middleware.py`)를 새로 만들고, 서버를 실제로 띄워 두 종류의 HTTP 처리기(httptools · h11) 모두에서 3MB 요청이 400 · 411 · 413으로 막히는 것을 확인했다.
  - NUL 문자 · 구간 순번 · 제약 위반 구분: 고치는 데 몇 줄이고, "틀린 입력은 422, 서버 문제는 500"이라는 약속을 지킨다.
  - 대응표 · `fields` 설명: 다음 기능(앱 동기화, 웹)이 이 문서만 보고 코드를 짠다.
  - 구조 정리 4개: 에러 모양은 `errors.py`의 `error_response` 한 곳, 기간 타입은 `schemas/stats.py` 한 곳, 10분 인정 상수는 서비스로 옮겼다.
- 고쳐서 수용한 지적: `_Scope`의 칸을 "부를 때마다 계산하는 속성"으로 바꾸라는 제안은 그대로 따르면 통계가 전부 깨진다(SELECT와 GROUP BY에 들어간 식이 서로 다른 식으로 취급되어 Postgres가 거절한다 — 테스트 17개가 실패해 알았다). "한 번만 계산해 두는 속성"(`cached_property`)으로 바꾸고 이유를 주석에 적었다.
- 거절할 지적과 이유:
  - 저장 직후 다시 읽었는데 없는 경우의 500 테스트: 정상 흐름에서는 일어나지 않는 분기라, 억지로 실패를 만들어 넣는 테스트를 유지하는 비용이 더 크다. "다른 제약 위반은 숨기지 않고 그대로 올린다"는 테스트 하나는 추가했다.
- 다음에 고칠 것: Q-005(주 목표를 주마다 저장할지), Q-006(서버 상한을 넘는 기록)의 답에 따라 F-010 · F-011에서 맞춘다.
