## 지적 (있을 때)
- [주의] [확실] `GET /stats`의 anchor가 9999년 근처면 422가 아니라 500 INTERNAL이 나간다 — server/app/services/stats_service.py `_period_range` — diff를 읽고, `date(9999,12,1).replace(day=28)+timedelta(days=4)`는 OverflowError, `date(9999+1,1,1)`은 ValueError가 나는 것을 파이썬 날짜 계산만 따로 돌려 확인(앱 요청은 실행하지 않음). 두 예외는 `errors.py`의 catch_unexpected 미들웨어가 500으로 바꿈 — anchor 범위를 제한(예: 2000~2100년 밖이면 AppError 422 VALIDATION)하거나 `_period_range`에서 OverflowError·ValueError를 잡아 422로 바꾼다.
- [주의] [확실] 경계값 테스트가 비어 있다: 월말 · 연말 · 윤년 · 연도를 걸치는 주 · 서머타임 있는 시간대 — server/tests/test_stats.py — 테스트 이름과 anchor 값을 diff로 확인. 쓰인 anchor는 2026-11-15, 2026-10-15, 2026-06-01, 2099-01-15, 기본값뿐. 12월(`_period_range`가 다음 해 1월 1일을 만드는 경로), 2월 윤년(2028-02), 12월 말~1월 초에 걸친 주(`_goal_weeks`의 first_monday가 전년도가 되는 경우), America/New_York 같은 서머타임 시간대는 어떤 테스트도 지나가지 않음. 월요일 0시 경계 · 서울 UTC 날짜 경계 · 빈 기간(2099)은 있음 — anchor 2028-02-10(29칸), 2026-12-15(31칸 · end 2027-01-01), 2027-01-15(첫 주가 2026-12-28 시작) 케이스와, 서머타임 전환 주를 포함한 tz 케이스를 추가한다.
- [제안] [추정] DB 쪽 실패를 사용자 문구로 바꾸는 코드가 없고(IntegrityError 처리 없음), 롤백을 확인하는 테스트도 없다 — server/app/services/run_service.py `upsert_run`, server/tests/conftest.py — 확인한 범위: 서비스 · 모델 · conftest를 읽음. CHECK 4개는 pydantic이 먼저 막아 거의 닿지 않지만, 인증 직후 회원이 지워지면 FK 위반이 나 500 INTERNAL이 된다(원래는 401이 자연스러움). 테스트 세션이 savepoint 위에서 돌아 commit 실패 뒤 롤백 동작은 지금 구조로 볼 수 없음. [확실]이 되려면: 로그인 뒤 회원을 지우고 PUT을 보내 응답 코드 확인 — `except IntegrityError`에서 rollback 후 401(회원 없음) 또는 409/422로 바꾸고, 그 경우를 테스트 한 건으로 남긴다.
- [제안] [추정] tz 값 가운데 파이썬 `ZoneInfo`는 받지만 Postgres `timezone()`이 모르는 이름이 있으면 500이 된다 — server/app/services/stats_service.py `_zone` · `_daily_totals` — 검증은 파이썬 쪽(ZoneInfo)만 함. [확실]이 되려면: `zoneinfo.available_timezones()`를 개발 DB의 `pg_timezone_names`와 대조해 다른 이름이 있는지 확인 — 있으면 DB로 한 번 확인하거나(`SELECT now() AT TIME ZONE :tz`) 실패를 422로 변환.
- [제안] [확실] `elapsed_s`와 `started_at`~`ended_at` 사이의 일관성을 검사하지 않아, 1분 구간에 elapsed_s=86400을 보내도 201이고 `counted`가 true가 된다 — server/app/schemas/run.py `RunIn._check`, tests/test_runs.py — diff를 읽음. 인정 여부를 서버가 정하는 취지(클라이언트 값을 믿지 않음)와 어긋나는 틈. 허용 오차를 두고 어긋나면 422로 막고 테스트 1건을 더한다(앱이 일시정지 시간을 elapsed_s에서 빼는지 D-007/feature.md로 먼저 확인).
