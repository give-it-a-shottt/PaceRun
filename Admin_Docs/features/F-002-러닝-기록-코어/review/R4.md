## 지적 (있을 때)
- [신규] [주의] [확실] 권한 없음 안내 문구가 실제 요구와 어긋난다. `LocationAlert`는 "위치 권한을 '항상 허용'으로 바꿔 주세요"라고 안내하지만, feature.md "설계 의도와 다른 점"과 `useStartRun`은 '앱 사용 중' 권한만 있으면 시작할 수 있고 '항상 허용'은 필수가 아니라고 한다. 사용자가 필요 이상으로 높은 권한을 요구받는다 — `components/run/LocationAlert.tsx`(COPY.permission.message), `services/permissions.ts`(getLocationAccess의 foreground/background 구분) — 두 파일과 feature.md를 직접 읽음 — 문구를 "위치 권한(앱 사용 중 이상)이 필요해요"처럼 실제 조건에 맞추거나, 필수로 만들 의도라면 feature.md의 다른 점 항목을 고친다. 문구 자체는 사용자가 정할 부분이라 OPEN_QUESTIONS에 올릴지 확인 필요.
- [신규] [주의] [추정] 자유 러닝 외 세 모드를 시작 전 설정 시트에서 고를 수 있고, 고르면 소리 안내 · 전용 표시 없이 기록만 되어 저장된다. 인터벌은 구간이 'run' 한 개(전체 시간)로만 저장되고 km 구간도 없다. F-003이 들어오기 전에 쌓인 이런 기록이 F-004 · F-006의 "같은 모드 지난 기록 비교"에 섞일 수 있다. "자유 러닝만 온전"은 알려진 범위이나, 시트에서 막을지(비활성 · 안내 문구) 그대로 열어 둘지는 사용자가 정할 선택이다 — `components/run/RunSetupSheet.tsx`(MODE_ORDER 4개 모두 선택 가능), `domain/modeCues.ts`(interval · cadence · pacemaker는 cues 빈 배열), `domain/runEngine.ts`(firstSegmentKind, finish) — modeCues · runEngine은 읽음, F-004 비교 쿼리는 아직 없어 실제 섞이는지는 미확인 — [확실]이 되려면 F-004의 "지난번 비교" 설계에서 mode만으로 비교하는지 확인. 고치는 방법: OPEN_QUESTIONS에 "F-003 전까지 다른 모드 선택 처리"를 올리고 결정 전 임시 처리를 feature.md에 적는다.
- [신규] [제안] [확실] 코드가 정한 동작이 feature.md · 설계 문서에 적히지 않았다. (1) 자유 러닝 목표 시간을 채워도 자동 종료 · 음성 안내 없이 화면 문구만 "목표를 채웠어요"로 바뀐다(`domain/runView.ts` freePrimary). Q-004는 목표값의 범위 · 칸 · 기본값 · '제한 없음'만 다루고 "목표 도달 때 동작"은 없다. (2) 카운트다운 화면에 [취소]가 있고 취소하면 홈으로 간다(`app/run/countdown.tsx`). feature.md는 카운트다운 화면 모양만 언급한다. — 두 파일 직접 읽음 — feature.md "설계 의도와 다른 점"에 두 줄을 더하고, (1)은 Q-004에 항목을 추가하는 것을 제안.
- [제안] [확실] 이번 기능에서 부르는 곳이 없는 코드가 feature.md "바뀐 파일"에 없다: `db/runsRepo.ts`의 listFinishedRuns · getPreviousRunOfMode · getRunPoints · getRunSegments, `services/runHistory.ts`의 loadRunDetail. 패킷은 "F-004 · F-006용"이라 하지만 문서에는 이 사실이 없어 설계 의도(완료 기준 10개)에 없는 기능으로 읽힌다 — git grep으로 호출처 없음 확인(테스트 제외) — feature.md 결과에 "다음 기능용으로 미리 둠" 한 줄을 적거나, 쓰는 기능에서 추가한다.
