## 지적 (있을 때)
- [주의] [확실] 앱 프로세스가 죽었다 위치 작업으로 되살아나거나(restoreAndContinue), 앱을 다시 열어 "아직 기록 중"으로 판정돼 화면만 다시 붙는 경우(checkPendingRun의 stillRunning 분기)에 `startRunControl`(잠금화면 [일시정지]/[재개] 버튼 리스너)과 `prepareVoice`(음악 볼륨 낮추기 설정)를 다시 부르지 않는다. 시작 때만 `beginTracking`/`prepareVoice`가 불린다 — services/runController.ts `restoreAndContinue` · `checkPendingRun` — 코드를 직접 읽어 호출이 없음을 확인. 실제로 버튼이 먹통이 되는지는 실기기에서만 알 수 있음(완료 기준 4 · D-009 "잠금화면 버튼", 실기기 확인 목록과 연결) — 두 경로에서 알림 리스너 등록과 `prepareVoice(config.mode === 'cadence' ? 'mix' : 'duck')`를 다시 부른다(`continuePendingRun`은 이미 `beginTracking` + `prepareVoice`를 부르므로 같은 순서를 따르면 됨). 테스트 "화면 없이 되살아남"은 상태 복원만 확인하고 알림 · 음성 재등록은 확인하지 않는다.
- [주의] [추정] 알림 권한을 요청하는 호출부가 F-002 안에 없다. `requestNotificationAccess`는 정의만 있고 부르는 곳이 없으며(전체 grep), 권한 안내는 온보딩 ONB_01_001(F-004 이후)에서 하도록 문서가 잡혀 있다. 그 전에는 `showRunControl`이 "권한 없으면 버튼 없이 진행"으로 빠져 완료 기준 4의 "잠금화면 알림의 [일시정지]/[재개]"가 새로 설치한 기기에서는 동작하지 않을 수 있다 — services/runNotification.ts `showRunControl`, services/permissions.ts — 코드 읽기까지만. 안드로이드 13 이상 새 설치 상태에서 권한 창이 뜨는지 / 알림이 보이는지 에뮬레이터로 확인하면 [확실]이 된다 — 러닝 시작 흐름(useStartRun)에서 위치 권한 뒤에 알림 권한을 한 번 요청하거나, feature.md "설계 의도와 다른 점"에 "알림 권한은 온보딩 전까지 요청하지 않는다"를 적는다.
- [주의] [확실] 사용자가 정할 선택이 질문 없이 코드에 들어갔다. ① 자유 러닝 목표 시간에 "제한 없음" 선택지(가장 짧은 값에서 한 번 더 줄이면 null) — 기획 Flow A는 "자유 20분"이고 시간 제한 없음 UI는 기획에 없다(데이터 모델의 null 허용만 있음). ② 목표값 범위 · 한 칸 크기(자유 10~120분/5분, 인터벌 30~600초/30초·1~20회, 케이던스 150~190/5, 페이스 4'00"~10'00"/10초, 거리 1~21km 등)와 페이스메이커 기본값 6'30"/3km — domain/runConfig.ts `CONFIG_LIMITS` · `defaultConfigFor`, components/run/configFields.ts `freeFields`. ③ [10분만 뛰기]는 '마지막 설정'을 바꾸지 않는다(home.tsx `remember: false`, 코드 주석에만 있음). 위 셋은 feature.md "설계 의도와 다른 점"에 적혀 있지 않다(시작 전 설정의 −/+ 칸 자체는 적혀 있음) — 해당 파일 직접 읽음 — OPEN_QUESTIONS에 "목표값 범위와 '제한 없음'을 허용할까?"를 올리고, 임시 처리는 지금 값으로 적는다. 목표 시간을 채워도 안내 없이 계속 기록하는 동작(runView.ts `freePrimary`)도 같이 적어 두면 좋다.
- [제안] [확실] 기획 Flow A는 "{3초 카운트다운 + 음성 '시작합니다'}"인데, 코드는 카운트다운 중에는 소리가 없고 카운트다운이 끝나 러닝이 시작될 때(`startRun`의 start 안내) 말한다 — app/run/countdown.tsx, domain/runEngine.ts `startRun` — 해당 파일 직접 읽음 — 카운트다운 시작 때 말하게 하거나, feature.md "설계 의도와 다른 점"에 "시작합니다는 러닝 시작 시점에 말한다"를 적는다.
- [제안] [확실] GPS 신호 약함(RUN_02_001)은 기획에서 토스트(기본 3초)인데, 코드는 신호를 잡을 때까지 계속 떠 있는 토스트 모양 안내(GpsNotice)다. 코드 주석과 screens.md에는 있지만 feature.md "설계 의도와 다른 점"에는 없다 — components/run/GpsNotice.tsx, useStartRun.ts — 직접 읽음 — feature.md 다른 점에 한 줄 추가.
- [제안] [확실] F-002 범위 밖 용도의 코드가 들어 있다(호출부 없음): `db/runsRepo.ts`의 `listFinishedRuns` · `getPreviousRunOfMode`, `services/runHistory.ts`의 `loadRunDetail`(F-004 · F-006용). 완료 기준에 없고 단위 테스트도 없다 — 전체 grep으로 호출부 없음 확인 — 해당 기능에서 만들 때 넣거나, 남기려면 feature.md 결과에 "뒤 기능 대비"로 적는다.
