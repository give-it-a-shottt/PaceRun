## 최종 판정 (AI 위임 판정 — 사용자 확인 전)
- 수용할 지적과 이유: [주의] 8개 가운데 6개와 [제안] 대부분.
  - 위치 '항상 허용': 요청을 없애고 앱 설정(app.json)에서도 권한을 뺐다. 화면이 꺼져도 '앱 사용 중' 권한과 알림을 띄운 서비스만으로 위치가 들어오고, 필요 없는 권한은 받지 않는 편이 사용자에게도 스토어 심사에도 낫다. 기획 문서(온보딩에서 '항상 허용' 요청)와 달라지는 선택이라 Q-007로 올렸다. 이 변경으로 "요청 오류 때 시작이 막힘"과 "안내 문구" 지적도 함께 풀렸다.
  - 남는 알림 · 음성 오류: 뛰는 사람이 화면을 안 보는 앱이라, 눌러도 안 되는 알림이나 낮아진 채 안 돌아오는 음악은 바로 불편으로 이어진다.
  - 세 모드의 안내 없음: 따로 막지 않고 F-003(인터벌 · 발걸음 박자 · 페이스메이커 안내)을 바로 이어서 넣었다. 안내 없는 기록이 쌓일 틈이 없다.
  - 겹침 · 늦은 위치 · 남은 줄 · 점 묶어 저장 · 줄 서지 않는 쓰기: 모두 고치고, 계산 쪽은 테스트를 붙였다(늦게 도착한 위치, 여러 점 묶어 넣기 등).
  - 문서: 목표 시간을 채우면 음성으로 한 번 알리게 바꾸고(자동 종료는 없음), 카운트다운 [취소]와 미리 만들어 둔 함수를 feature.md에 적었다. architecture.md · data-model.md를 코드에 맞췄다. 순수 계산 파일은 domain 폴더로 옮겼다.
- 실기기로 넘긴 지적: 화면 없이 되살아나는 경로([주의]). 에뮬레이터에서는 "강제 종료 → 다시 열기"까지만 확인된다. feature.md "실기기 확인 목록"에 넣었다. 이것 때문에 STATUS는 [일부]로 둔다.
- 거절할 지적과 이유:
  - 시작 · 복구 화면 훅의 테스트([주의]): 화면 부품을 테스트에서 띄우는 도구(React Native 테스트 환경)를 새로 들여야 한다. 지금은 순수 계산과 진행 관리자만 테스트하기로 한 구조(D-001)라, 겹침 판단을 진행 관리자 안으로 옮겨 거기서 테스트했다(시작 중 다시 시작, 종료 두 번, 복구 확인 겹침). 훅 자체의 테스트는 두지 않는다.
  - 진행 관리 파일을 둘로 나누기: 복구 함수들도 같은 모듈 변수(진행 상태 · 타이머 · 저장 줄)를 함께 써서, 나누면 그 변수들을 밖으로 내보내야 한다. 지금 길이(약 430줄)에서는 얻는 것보다 잃는 것이 크다.
  - 종료 저장이 계속 실패할 때의 탈출구: 저장에 실패해도 러닝은 이어지고 진행 값은 매초 따로 저장되고 있어, 앱을 닫았다 열면 "여기까지 저장"으로 빠져나올 수 있다. 화면에 버튼을 더 두지 않는다.
  - GPS 요청 취소: expo-location에는 한 번짜리 위치 요청을 취소하는 방법이 없다. 다시 시도 횟수에 상한(약 2분)이 이미 있다.
