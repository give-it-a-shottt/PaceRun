## 설계 의도 (AI 초안 — 사용자 위임, 확인 전)
출처: pacerun-design.md 0-2(P4), 0-4 IA의 RUN_*, 0-5 Flow A · B, 5장, D-004, D-005

- 이 기능이 해결하는 문제: 뛰는 중 안내 · 기록이 끊김(P4) — 화면을 끄거나 다른 앱을 켜도 기록이 이어져야 하고, 일시정지 뒤 먹통이 되거나 기록이 사라지면 안 된다.
- 완료 기준(무엇이 되면 끝인지):
  1. [시작] → 시작 전 설정 시트(모드 4개 · 목표값 · 마지막 설정 기억) → 3초 카운트다운 → 러닝 중 화면으로 간다. [10분만 뛰기]는 시트 없이 카운트다운으로 간다.
  2. 러닝 중 화면에 경과 시간 · 거리 · 평균 페이스 · 최근 안내가 1초마다 갱신된다. 화면을 끄거나 다른 앱을 켜도 위치 기록이 이어진다.
  3. 경과 시간은 시작 시각과 지금 시각의 차이로 계산한다(일시정지 시간 제외). 타이머가 늦게 불려도 틀리지 않는다.
  4. [일시정지] → [재개] / [길게 눌러 종료](1.5초 + 진행 표시 + 진동). 잠금화면 알림의 [일시정지] / [재개]로도 된다. 자동 일시정지는 없다.
  5. 10분을 채우면 "오늘 1회 인정!" 음성 + 토스트. 10분 전에 끝내려 하면 "더 뛰기 / 그냥 종료"를 묻고, 그냥 종료하면 저장하되 횟수에는 넣지 않는다.
  6. GPS가 10초 넘게 끊기면 거리 계산을 멈추고 음성으로 1번 알리며 화면에 '찾는 중 · 잠시 멈춤'을 보여 준다. 타이머는 계속 가고, 신호가 돌아오면 그 자리부터 다시 잰다.
  7. 진행 값과 위치 점을 약 1초마다 폰 DB에 저장한다. 앱이 강제 종료된 뒤 다시 켜면 "이어서 / 여기까지 저장"을 묻는다.
  8. 위치 권한이 없으면 이유와 [설정 열기]를 보여 준다. 배터리 최적화를 풀지 않았으면 시작 전 설정 시트에 경고 배너를 띄운다. GPS 신호를 못 잡았으면 토스트로 알리고 그냥 시작할 수 있다.
  9. 끝내면 완료 요약(시간 · 거리 · 평균 페이스)을 보여 주고 [확인]으로 홈에 돌아간다.
  10. 러닝 화면은 OS가 다크면 Dark로 보인다(설정 '러닝 화면 테마'가 '항상 밝게'면 Light).
- 화면: `/run/countdown`(카운트다운), `/run/active`(러닝 중 · 일시정지 · 주머니 모드 · GPS 끊김), `/run/summary/[id]`(완료 요약), 홈 위 시작 전 설정 시트. 홈 탭은 [시작] · [10분만 뛰기] 버튼과 복구 창만 있는 임시 화면이다(F-004에서 완성).
- API: 없음(폰 안에서만 동작)
- 데이터: runs · run_points · run_segments에 쓴다. 복구용으로 active_run 테이블(1줄)을 추가한다.

- 완료 요약의 "지난번 비교", 이번 주 칸 칠하기, 작은 지도 → F-004, F-006
- 주머니 모드(RUN_01_005)는 화면만 만들어 두고, 실기기에서 화면 꺼짐이 불안정할 때만 쓴다(조건부).

## 실기기 확인 목록 (사용자 — 에뮬레이터로는 확인 불가)
- 화면을 끄고 주머니에 15분: 거리 · 시간이 끊기지 않는가
- 음악을 틀어 둔 채 안내가 나올 때: 음악 볼륨이 낮아졌다가 돌아오는가
- 잠금화면 알림의 [일시정지] / [재개]가 화면을 켜지 않고도 되는가
- 이어폰의 재생 · 정지 버튼이 음악만 멈추고 기록은 계속되는가, 전화가 와도 기록이 계속되는가
- 앱을 최근 앱 목록에서 밀어 없앤 뒤 다시 켰을 때: 러닝이 이어지고 있거나 복구 창이 뜨는가
- 러닝 중 앱을 밀어 없앤 채 2~3분 더 뛴 뒤 열었을 때: 그동안의 거리가 이어져 있는가(화면 없이 되살아나는 경로 — 2차 리뷰 R3)

- 바뀐 파일 (모두 `app/src/` 아래)

- 실제 구조
  - 계산은 전부 `runEngine`의 순수 함수가 한다. `runController`는 "위치가 왔을 때 · 1초 타이머가 울렸을 때 계산 함수를 부르고, 결과를 화면 상태 · DB · 음성으로 보내는" 일만 한다(D-005).
  - 진행 값 · 새 위치 점 · 복구용 상태(active_run)를 약 1초마다 한 트랜잭션으로 저장한다. 저장에 실패한 점은 버리지 않고 다음 저장 때 다시 넣는다.
  - 앱을 켰을 때 끝나지 않은 러닝이 있으면 "마지막 저장이 30초 안인가"로 판단한다. 30초 안이고 위치 받기가 돌고 있으면 화면만 다시 붙이고, 아니면 "이어서 / 여기까지 저장"을 묻는다. 꺼져 있던 시간은 일시정지로 친다.
  - 끝내는 동안에는 타이머를 멈추고 위치도 받지 않는다. 종료를 두 번 눌러도 저장은 한 번이다. 저장에 실패하면 타이머를 다시 돌려 러닝을 이어 간다(1차 리뷰 R3 지적 반영).
  - 진행 관리자는 파일이 읽히는 순간 위치 받을 곳을 등록한다. 앱이 죽었다 위치 작업으로 되살아나도 위치를 받고, 그때 잠금화면 버튼 · 음성도 다시 붙인다.
  - 폰 DB 쓰기는 모두 `withWriteTransaction`(늘 쓰는 연결 + 한 줄 세우기)을 거친다. 매초 연결을 새로 열지 않는다(R2 지적 반영).
  - 화면이 꺼져 있거나 앱이 뒤에 있으면 화면 상태 갱신을 건너뛴다(계산 · 저장 · 음성은 계속).
  - 음성 말하기가 오류를 내거나 끝났다는 신호가 15초 안에 오지 않으면 끝난 것으로 보고 음악 볼륨을 되돌린다(2차 리뷰 R3 지적 반영).
  - 강제 종료 뒤 복구할 때(여기까지 저장 · 오래 끊김)는 위치 받기와 잠금화면 알림을 함께 끈다. 시작 직후 죽어 복구할 수 없게 남은 '진행 중' 줄은 다음에 앱을 열 때 닫는다(R2 · R3 지적 반영).
  - 위치 점은 100개씩 묶어 한 문장으로 넣는다. 일시정지 전에 잡힌 위치가 재개 뒤 늦게 도착하면 버린다.
  - 화면은 `describeRun()`이 준 글자를 그리기만 한다. 경과 시간은 저장하지 않고 `지금 시각`으로 매번 계산한다.
  - 러닝 화면 묶음(`run/_layout`)만 OS 다크 설정을 따라 Dark가 된다.
- 설계 의도와 다른 점
  - 위치 '항상 허용'을 요청하지 않는다(기획은 온보딩에서 '항상 허용' 요청). 안드로이드에서는 알림을 띄운 포그라운드 서비스로 시작하면 '앱 사용 중' 권한만으로 화면이 꺼져도 위치가 들어온다(설치된 expo-location 소스에서 확인, 에뮬레이터에서 '앱 사용 중'만 준 채 기록 확인). 앱 설정에서도 그 권한을 뺐다 → Q-007. (2026-11-23 다시 빌드해 확인: 설치 파일의 권한 목록에 백그라운드 위치 · 마이크 · 저장소 읽기/쓰기가 없고, 그 빌드로 앱을 뒤로 보낸 35초 동안에도 거리가 기록됐다)
  - 자유 러닝의 목표 시간을 채우면 음성 · 화면으로 한 번 알리고 러닝은 이어진다(자동 종료 없음). 직접 끝낼 때까지 기록한다.
  - 카운트다운 화면에 [취소]가 있다(누르면 홈으로). "시작합니다" 음성은 카운트다운이 끝나 러닝이 시작될 때 나온다.
  - 시작 직후 첫 위치는 20초까지 기다린 뒤 끊김으로 본다(그 뒤는 10초). 위치 서비스가 켜지는 시간을 끊김으로 오해하지 않으려는 것.
  - 신호가 돌아오면 화면의 최근 안내 줄을 "GPS 신호를 다시 잡았어요"로 바꾼다(음성은 끊길 때 1번만).
  - 일시정지 화면의 버튼 글자는 피그마 "다시 시작"이 아니라 설계 문서의 "재개"를 썼다(잠금화면 알림 버튼과 같은 말). 시작 전 설정의 자유 모드 카드는 "자유 러닝"으로 나온다(피그마는 "자유").
  - 시작 전 설정에서 목표값을 고치는 화면이 피그마에 없어, 목표값 줄을 누르면 [−] 값 [+] 칸이 펼쳐지게 만들었다. 카운트다운 화면도 피그마에 없어 러닝 화면의 큰 숫자 스타일로 만들었다.
  - 10분 전 종료 확인 창은 러닝 화면이 Dark여도 Light로 그린다(피그마에 Light만 있다).
  - 주머니 모드(RUN_01_005)는 화면 부품만 있고 켜는 곳이 없다 → Q-003.
  - GPS 약함 안내(RUN_02_001)는 3초 토스트가 아니라 신호를 잡을 때까지 떠 있다. 시작 전 설정 시트가 열려 있으면 앱 토스트가 시트 뒤에 가려지기 때문이다. 약 2분 동안 못 잡으면 찾기를 멈추고 [그냥 시작하기]만 남긴다.
