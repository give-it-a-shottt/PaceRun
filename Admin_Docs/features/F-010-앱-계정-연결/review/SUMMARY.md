## 최종 판정 (AI 위임 판정 — 사용자 확인 전)
- 수용할 지적과 이유: [주의] 2개 전부와 [제안] 가운데 아래 하나를 뺀 전부.
  - 뒤늦은 401: 요청이 시작될 때의 로그인 판 번호를 잡아 두고, 답이 왔을 때 번호가 바뀌었으면 상태를 건드리지 않는다. 로그인돼 있지 않을 때는 토큰 갱신을 시작하지 않는다. 테스트 1개.
  - 보관함에 넣는 사이의 로그아웃: 넣은 뒤에 판 번호를 한 번 더 보고, 바뀌었으면 넣은 토큰을 다시 지우고 서버에도 폐기를 알리며 액세스 토큰을 되살리지 않는다. 테스트 1개(로그아웃의 지우기보다 쓰기가 늦게 닿는 경우).
  - 읽기 실패한 러닝은 그 한 건만 건너뛴다. 시간 제한을 본문을 다 읽을 때까지 건다. 동기화의 결과는 아직 로그인돼 있을 때만 적는다. 테스트 3개.
  - 구조: 오류를 만드는 함수 하나로, 목록 응답도 모양 확인 함수로, 상태 글자의 겹친 조건을 작은 함수로 뺐다.
  - feature.md "설계 의도와 다른 점"에 "로그인 뒤 동기화를 기다리지 않고 동기화 상태 화면으로 간다"를 적었다(설계 의도 칸은 고치지 않았다).
- 거절할 지적과 이유:
  - 가입은 됐는데 보관함 저장이 실패한 경우: 아주 드물고(폰의 보관함 고장), 다시 시도하면 "이미 가입한 이메일이에요. 로그인해 주세요"가 길을 알려 준다. 이 경우만을 위한 문구 · 흐름을 더하지 않았다.
- 다음에 고칠 것: Q-006의 답에 따라 서버 상한을 넘는 기록의 처리를 바꾼다.
- 알려 둘 것: 2차에서 나온 [주의] 2개의 수정은 리뷰어가 다시 보지 않았다(3차를 돌리지 않았다). 테스트로 겹치는 순서를 만들어 확인했지만, 로그인 · 토큰 코드라 한 번 더 보는 것도 방법이다.
