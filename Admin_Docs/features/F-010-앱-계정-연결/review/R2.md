## 지적 (있을 때)
- [신규] [주의] [추정] 토큰 갱신이 판 번호 확인을 통과한 뒤 `await SecureStore.setItemAsync(REFRESH_TOKEN_KEY, 새 토큰)`을 기다리는 사이에 로그아웃하면, 그 뒤 판 번호를 다시 보지 않고 `keepAccessToken(tokens)`으로 액세스 토큰을 메모리에 되살린다. 보관함 쓰기와 로그아웃의 지우기가 네이티브에서 순서대로 처리되지 않으면 리프레시 토큰이 로그아웃 뒤에 남아, 다음에 켤 때 `restoreSession`이 이메일 없는 로그인 상태로 연다 — 위치: `app/src/services/session.ts` `refreshAccessToken`(판 번호 확인 → `setItemAsync` → `keepAccessToken`) · `logOut` — 확인한 범위: 패키지 diff의 session.ts 전체, 테스트 목록(“갱신하는 사이에 로그아웃”은 서버 요청 중의 겹침만 다룸). expo-secure-store가 Android에서 쓰기 · 지우기를 순서대로 처리하는지는 보지 않음 — [확실]이 되려면 expo-secure-store의 Android 비동기 함수가 한 줄로 처리되는지 확인하거나, `setItemAsync`가 늦게 끝나게 만든 테스트로 확인한다 — 고치는 방법: `setItemAsync` 뒤에 `epoch !== sessionEpoch`를 한 번 더 보고, 바뀌었으면 넣은 토큰을 지우고 서버에 폐기를 알린 뒤 `SessionExpiredError`를 던진다(`keepAccessToken`은 그 뒤에만).
- [신규] [주의] [확실] 로그아웃 뒤에 늦게 끝난 요청이 401을 받으면 상태가 `signedOut`에서 `expired`로 바뀐다. `authorizedRequest`는 다시 보내기 직전에 판 번호를 잡고(`const epoch = sessionEpoch`), `refreshAccessToken`도 시작할 때 판 번호를 잡으므로, 그 사이에 로그아웃했으면 둘 다 "지금 판"으로 보고 `expireSession`이 통과한다 → 이메일 없는 "다시 로그인이 필요해요" 화면이 된다. 토큰이 남지는 않는다. 동기화 상태 화면은 동기화 중에도 [로그아웃]을 막지 않아서(`my/sync.tsx` `handleLogOut`) 겹칠 수 있다. 다만 서버가 그 사이 액세스 토큰을 거절해야(만료 등) 생기므로 드물다 — 위치: `app/src/services/session.ts` `authorizedRequest` · `refreshAccessToken` · `expireSession` — 확인한 범위: session.ts 전체, `git show fdda674:app/src/app/my/sync.tsx` 앞 80줄 — 고치는 방법: `authorizedRequest`에 들어올 때 판 번호를 잡아 갱신 · 만료 처리에 넘기거나, `expireSession`에서 `useAuthStore.getState().status === 'signedIn'`일 때만 만료로 바꾼다.
