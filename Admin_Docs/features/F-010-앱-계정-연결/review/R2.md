## 지적
- [주의] [확실] 로그아웃과 진행 중인 토큰 갱신이 겹치면 로그아웃 뒤에 새 리프레시 토큰이 보관함에 다시 저장될 수 있다. 순서: 동기화 중 `refreshAccessToken()`이 토큰 A로 `/auth/refresh`를 보냄 → 사용자가 [로그아웃] → `logOut()`이 A를 읽고 보관함을 비우고 A로 `/auth/logout` → 갱신 응답이 돌아와 `SecureStore.setItemAsync(REFRESH_TOKEN_KEY, B)`. 그러면 서버에서는 B가 살아 있고(로그아웃은 이미 바뀐 A로 보냄), 폰에도 B가 남는다. 다음에 앱을 켜면 `restoreSession()`이 B를 보고 `signedIn`(이메일은 null)으로 열고 자동 올리기가 로그아웃한 계정으로 다시 돈다. 같은 겹침에서 401 다시 보내기 길(`authorizedRequest` → `freshAccessToken(true)`)은 비어 있는 보관함을 보고 `expireSession()`을 불러 상태를 `signedOut`에서 `expired`로 덮어쓴다 — 위치: `app/src/services/session.ts` `logOut` · `refreshAccessToken` · `expireSession` — 확인한 범위: diff의 session.ts 전체와 `my/sync.tsx`의 `handleLogOut`(동기화 중 로그아웃을 막지 않음)을 읽음. 실행해서 재현하지는 않음(갱신 요청이 가는 짧은 동안에만 생김) — 고치는 방법: 세션 세대 번호(로그인 · 로그아웃마다 +1)를 두고 `refreshAccessToken`이 응답을 받은 뒤 세대가 바뀌었으면 B를 저장하지 않고 B로 `/auth/logout`을 보내 폐기한다. 또는 `logOut()`이 먼저 `refreshing`이 끝나기를 기다린 뒤 그때의 토큰을 읽어 폐기한다. `expireSession()`은 상태가 `signedIn`일 때만 `expired`로 바꾼다.
- [제안] [확실] 내려받기가 러닝마다 `GET /runs/{id}`를 하나씩 차례로 보내고(네트워크 N+1), [지금 동기화]마다 목록을 처음부터 끝까지(최대 200쪽)다시 읽는다. 새 폰에서 수백 건이면 요청 수백 번을 한 줄로 기다린다(패킷 "확인하지 못한 것: 기록 수백 건의 내려받기 시간") — 위치: `app/src/services/sync.ts` `downloadMissing` — 확인한 범위: diff의 sync.ts. 목록 · 상세 API 모양은 패킷 설명만 봄(D-010에 "무겁다"고 적은 설계 선택) — 고치는 방법: 상세 요청을 3~4개씩 묶어 동시에 보내거나, 나중에 서버에 여러 건을 한 번에 주는 API를 두는 것을 검토한다. 지금 규모에서는 그대로 두어도 된다.
- [제안] [확실] 서버 응답을 모양만 확인하고 크기는 확인하지 않는다: `fromServerRun()`은 `route` · `segments` 개수, `plan_label` 길이, 위도 · 경도 범위에 상한이 없어 잘못된 응답이 오면 큰 배열을 그대로 한 트랜잭션에 넣는다 — 위치: `app/src/domain/syncMapping.ts` `fromServerRun` — 확인한 범위: diff의 syncMapping.ts — 고치는 방법: 올릴 때 쓰는 `SERVER_LIMITS`(경로 20000점 · 구간 1000개 · 이름 50자)를 내려받을 때도 적용해 넘으면 null로 건너뛴다.
- [제안] [추정] 주소 환경변수가 비어 있으면 릴리스 빌드에서도 `http://10.0.2.2:8000`으로 간다. 안드로이드 릴리스는 기본으로 평문 HTTP를 막아 비밀번호가 평문으로 나가기보다 연결 실패가 될 것으로 보이지만, 앱 코드에 그 보장이 없다 — 위치: `app/src/services/apiClient.ts` `apiBaseUrl` — 확인한 범위: apiClient.ts, `app/app.json`(평문 허용 설정 없음 확인). 생성된 AndroidManifest(release)의 `usesCleartextTraffic`은 열지 않음 — [확실]이 되려면 릴리스 빌드의 매니페스트를 확인한다 — 고치는 방법: `!__DEV__`에서 주소가 `https://`가 아니면 요청을 보내지 않고 오류로 알린다.
