## 지적 (있을 때)
- [신규] [제안] [확실] 러닝 한 건의 경로·구간을 읽다 실패하면 뒤의 러닝 올리기가 전부 멈춘다 — app/src/services/sync.ts uploadPending() — `getRun`은 `.catch(() => null)`로 건너뛰지만 바로 아래 `Promise.all([getRunSegments(id), getRunPoints(id)])`는 감싸지 않아 DB 읽기 오류가 runOnce까지 올라가 syncProblem이 'server'가 됨(패킷의 diff로 코드 확인, 실행은 안 함). 같은 러닝이 매번 맨 앞에서 걸리면 그 뒤 기록이 계속 못 올라감 — 같은 try/catch로 감싸 `unsendable += 1; continue` 처리하고 그 경우의 테스트 1개 추가.
- [신규] [제안] [확실] 가입은 서버에서 성공했는데 토큰·이메일 보관(SecureStore)이 실패하면 사용자에게 "처리하지 못했어요"(unknown)만 보이고, 다시 가입하면 "이미 가입한 이메일이에요. 로그인해 주세요"가 나옴 — app/src/services/session.ts startSession() · services/account.ts connectAccount() — 코드 확인(보관 실패 시 토큰은 도로 지우나 서버에 만든 계정·세션은 그대로). 드문 경우이고 안내 문구가 결국 로그인으로 이끄므로 제안 등급 — 보관 실패를 별도 종류로 구분해 "로그인해 주세요"를 안내하거나, 현재 동작을 feature.md에 알려진 한계로 적기.
- [신규] [제안] [추정] 요청 시간 제한(15초)이 응답 머리글을 받은 직후 해제돼, 본문을 받는 중에 멈추면 `response.json()`이 무기한 기다릴 수 있음 — app/src/services/apiClient.ts apiRequest() — 코드는 읽었으나 RN fetch의 본문 읽기 중단 동작은 실행해 보지 않아 [추정]. 실제로 멈추는지 느린 본문을 흘리는 가짜 서버로 확인하면 [확실]이 됨 — `clearTimeout`을 본문 읽기 뒤로 옮김.
- [신규] [제안] [추정] 동기화가 도는 중에 로그아웃하면, 늦게 끝난 runOnce가 syncProblem('expired')과 unsendableCount를 signedOut 상태에서 다시 적을 수 있음 — app/src/services/sync.ts runOnce() · services/session.ts logOut() — runOnce의 catch/finally와 logOut의 초기화 코드를 읽음. 화면이 signedOut에서 이 값들을 쓰는지(`domain/syncView.ts` describeAccount)는 열지 않아 [추정]. 로그아웃 직후 도는 동기화를 만들어 보면 [확실] 여부가 갈림 — runOnce 끝에서 status가 아직 signedIn일 때만 결과를 적기.
