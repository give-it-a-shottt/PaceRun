## 지적 (있을 때)
- [제안] [확실] 서버의 "elapsed_s ≤ ended_at − started_at + 5초" 검사를 앱이 맞추지 않는다. 끝 시각이 시작보다 빠른 기록은 ended_at만 started_at으로 올려 맞추는데(wall = 0), elapsed_s는 그대로라 서버가 422로 거절한다. 코드 주석("서버가 받게 한다")과 결과가 다르다. 거절되면 D-010대로 건너뛰고 "올릴 수 없는 기록"에 세므로 동작은 안전하다 — app/src/domain/syncMapping.ts `toRunUpload` — 서버 server/app/schemas/run.py `RunIn._check`와 api-list.md "러닝" 표(`elapsed_s` 칸)를 대조했다 — 올릴 때 elapsed_s를 (맞춘 ended_at − started_at + 5초) 이하로도 맞추거나, 주석을 사실대로 고치고 data-model.md Q-006 표에 한 줄 추가한다. (Q-006 임시 처리와 관련)
- [제안] [확실] 구간(segments)이 1000개를 넘으면 앞 1000개만 올리고 나머지를 조용히 버린다. 이 처리는 data-model.md "서버 상한을 넘는 드문 경우" 표에 없다(경로 · 페이스 · 라벨 · config · 24시간/300km만 있다) — `toRunUpload`의 `segments.slice(0, SERVER_LIMITS.segments)` — 표와 코드를 대조했다 — 표에 "구간 1000개 초과 → 앞 1000개만" 한 줄을 더한다. (Q-006 임시 처리와 관련)
- [제안] [확실] feature.md "설계 의도"의 API 목록에는 `GET /me`가 있는데 앱은 부르지 않는다(패킷의 앱 호출 목록에도 없다). 로그인 응답의 `user`로 충분해서 일 없는 호출을 뺀 것으로 보이지만 문서와 코드가 다르다 — feature.md "API" 줄 ↔ app/src/services 전체 호출부 — 설계 의도의 API 줄에서 `GET /me`를 빼거나 "앱은 쓰지 않음"을 적는다.
