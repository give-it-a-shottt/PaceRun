## 한눈에 보기
상태: [보완] (1차. 반영 뒤 2차 진행 중)
무엇을: 앱에서 가입 · 로그인해 계정을 연결하면, 폰에 쌓인 러닝 기록이 서버로 올라가고(같은 기록은 한 번만), 서버에만 있는 기록은 폰으로 내려온다. 그 뒤로는 러닝을 끝낼 때마다 알아서 올라간다. 💡 비유: 사진 자동 백업 — 찍은 사진은 먼저 폰에 있고, 계정을 연결해 두면 인터넷이 될 때 알아서 올라간다.
왜: 웹 대시보드에서 월 · 년 단위로 보려면 기록이 서버에 있어야 하고, 폰을 바꿔도 기록이 따라와야 한다(우선순위 4).

## 설계 의도 (AI 초안 — 사용자 위임, 확인 전)
출처: pacerun-design.md 0-4 IA(MY_01_002~004), 0-5 Flow E와 "동기화 규칙", 0-6 검수 기록의 "동기화 예외", decisions/D-004(폰에 먼저 저장) · D-006(토큰)

- 이 기능이 해결하는 문제: 기록이 폰 한 대에만 있으면 웹에서 볼 수 없고, 폰을 잃으면 기록도 사라진다. 그렇다고 로그인을 강제하면 처음 뛰기까지가 멀어진다 — 그래서 로그인은 나중에, 원할 때만 한다.
- 완료 기준(무엇이 되면 끝인지):
  1. 로그인하지 않아도 앱의 모든 기능이 그대로 된다. 내 정보 탭 위쪽에 "로그인 없이 사용 중"과 폰에만 있는 기록 수가 보인다.
  2. 동기화 상태 화면에 계정 연결 상태, 마지막 동기화 시각, 폰에만 있는 기록 수가 보이고 [계정 연결]로 로그인 화면에 간다.
  3. 이메일 + 비밀번호로 로그인하거나 가입한다. 틀린 입력(이메일 모양, 비밀번호 8자 미만, 확인 불일치)과 서버의 거절(이미 가입한 이메일, 이메일 · 비밀번호 틀림)을 화면에서 알려 준다. 비밀번호 찾기는 없다(MVP 제외).
  4. 로그인에 성공하면 폰의 끝난 러닝을 모두 올리고, 서버에만 있는 러닝을 폰으로 내려받는다(새 폰). 끝나면 동기화 상태 화면으로 돌아온다.
  5. 같은 러닝을 여러 번 올려도 서버에는 한 건만 남는다(폰이 만든 번호가 서버의 번호 — F-009).
  6. 로그인돼 있으면 러닝을 끝낼 때와 앱을 켤 때 알아서 올린다. 인터넷이 안 되면 기록은 폰에 남아 있다가 다음에 올라간다.
  7. 로그인이 만료되면(오래 쓰지 않았거나 다른 기기에서 토큰이 폐기됨) 올릴 기록은 그대로 두고 "다시 로그인이 필요해요"를 보여 준다. 다시 로그인하면 이어서 올라간다.
  8. 로그아웃하면 토큰을 지운다. 폰의 기록은 지우지 않는다.
- 화면: `/my`(위쪽 계정 영역과 "동기화 상태" 줄 추가), `/my/sync`(동기화 상태), `/my/login`(로그인), `/my/signup`(회원가입)
- API: POST /auth/signup · /auth/login · /auth/refresh · /auth/logout, PATCH /me(주 목표), PUT /runs/{id}, GET /runs, GET /runs/{id} — overview/api-list.md 그대로
- 데이터: 폰의 runs.sync_state(local → synced), settings.lastSyncAt을 쓴다. 테이블 변경 없음. 토큰은 SQLite가 아니라 expo-secure-store에 둔다. 폰 ↔ 서버의 칸 대응은 overview/data-model.md "폰 ↔ 서버 이름 대응".

범위 밖(다른 기능에서 · 하지 않는 것)

- 계획(plan_items) · 설정을 서버에 올리기(서버 API에 없다. 주 목표만 올린다 — 웹 대시보드의 "주 목표 달성 주 수"에 쓰인다)
- 한 폰에서 계정을 바꿔 가며 쓰는 경우의 기록 나누기
- 웹 대시보드(F-011)

- 바뀐 파일 (모두 `app/src/` 아래)

- 실제 구조
  - 층: 화면 → `account` · `sync` · `session`(서비스) → `apiClient`(요청 한 건) / `runsRepo`(폰 DB). 화면은 `authStore`를 읽기만 하고, 바꾸는 것은 서비스다. 글자는 `describeAccount()`가 만든다.
  - 토큰(D-006): 리프레시 토큰은 expo-secure-store에만, 액세스 토큰은 메모리에만 둔다. 요청 전에 액세스 토큰이 없거나 곧 만료되면 먼저 갱신하고, 그래도 401이면 한 번 더 갱신해 다시 보낸다. 갱신은 한 번에 하나만 한다(리프레시 토큰은 한 번 쓰면 바뀐다). 서버가 리프레시 토큰을 받지 않을 때만 "만료"로 바꾸고, 서버에 닿지 못한 것은 로그인을 풀지 않는다. 만료되면 토큰은 지우고 이메일은 남긴다(다시 로그인 화면에 채워 준다). 로그인 · 로그아웃할 때마다 "판" 번호를 올려서, 서버에 다녀오는 사이에 로그아웃했으면 늦게 온 토큰을 저장하지 않고 서버에도 폐기를 알린다(로그아웃한 폰에 로그인이 되살아나지 않게).
  - 동기화(D-010): "대기열"은 따로 만든 표가 아니라 `runs.sync_state = 'local'`인 끝난 러닝이다. 오래된 것부터 `PUT /runs/{id}`로 올리고 성공하면 `synced`로 바꾼다. 서버에 닿지 못함 · 서버 오류 · 만료면 거기서 멈추고(남은 것은 다음에), 서버가 "받을 수 없다"(409 · 413 · 422)고 한 러닝은 그것만 건너뛴다. 내려받기는 로그인 직후와 [지금 동기화]에서만 한다. 내려받다가 한 건을 받지 못하면(서버가 주지 않음 · 모양이 틀림 · 폰에 넣다 실패) 그 기록만 건너뛰고, 서버에 닿지 못함 · 서버 오류 · 만료면 멈춘다.
  - 올릴 때의 변환은 overview/data-model.md "폰 ↔ 서버 이름 대응" 그대로다: 경과 시간은 초로 내림, 목표값에서 `mode`를 빼고 snake_case로, 경로 20000점 초과는 고르게 솎기, 끝 시각은 "시작 + 경과 시간" 이상으로 맞추기, 24시간 · 300km 초과는 올리지 않음(Q-006).
  - 내려받은 러닝은 모양과 크기(서버가 받는 상한)를 확인한 뒤에만 폰에 넣는다(`fromServerRun`). 같은 번호가 폰에 있으면 덮어쓰지 않는다.
  - 동기화는 겹쳐 돌지 않는다. 도는 중에 다시 부르면 끝난 뒤 한 번 더 돈다.
- 설계 의도와 다른 점
  - 로그인된 상태 · 만료된 상태의 화면은 피그마에 없다(연결 안 된 상태만 있다). 글자는 AI가 지었다: "계정이 연결돼 있어요", "다시 로그인이 필요해요", [지금 동기화], [로그아웃]과 확인 창("로그아웃할까요? 기록은 이 폰에 그대로 남아요…"), "모든 기록이 서버에 올라가 있어요", "올릴 기록 N개", 실패 안내 두 가지, 회원가입 화면의 "이미 계정이 있어요 [로그인]".
  - 입력 오류 문구는 피그마 예시("이메일 형식이 올바르지 않아요")와 다르다: "이메일 주소를 확인해 주세요", "비밀번호는 8자 이상이어야 해요", "비밀번호가 서로 달라요", "이미 가입한 이메일이에요. 로그인해 주세요", "이메일 또는 비밀번호가 맞지 않아요"(AI가 지음).
  - 동기화 상태 화면의 줄 두 개는 누를 곳이 없어 꺾쇠 없이 그렸다(피그마에는 꺾쇠가 있다).
  - 자동 동기화는 올리기만 한다. 다른 폰에서 올린 기록은 로그인 직후나 [지금 동기화]를 눌러야 들어온다(D-010).
  - 주 목표는 폰의 값을 서버에 올린다. 서버의 값을 폰으로 가져오지 않는다(D-010).
  - 서버가 받지 않는 러닝(24시간 · 300km 초과, 서버가 거절한 러닝)은 "이 폰에만 있는 기록"에 계속 세고, 따로 한 줄로 알린다. 앱을 다시 켜면 거절된 러닝은 한 번 더 보내 본다(기억을 메모리에만 둔다).
  - 로그아웃해도 마지막 동기화 시각은 남는다.
  - 서버 주소: 개발 중에는 `http://`(암호화 없음)로 내 PC의 서버에 붙는다. 개발 빌드가 아니면(스토어에 올리는 빌드) `EXPO_PUBLIC_API_URL`에 `https://` 주소를 줬을 때만 요청을 보낸다 — 주소가 없거나 `http://`면 보내지 않는다(릴리스 빌드를 만들어 확인하지는 않았다).
- 에뮬레이터(Android API 37) + 내 PC의 서버로 확인한 것 (2026-11-23)
  - 내 정보 탭 위쪽 "로그인 없이 사용 중 · 기록 6개가 이 폰에만 저장돼 있어요", 동기화 상태 화면(연결 안 됨)
  - 로그인: 빈 칸으로 누르면 칸마다 안내, 없는 계정이면 "이메일 또는 비밀번호가 맞지 않아요"
  - 회원가입(키보드의 다음 · 완료로 칸 넘기고 보내기, 키보드 위로 버튼이 올라옴) → 동기화 상태 "계정이 연결돼 있어요 · 이 폰에만 있는 기록 0개" → 서버에 러닝 6건과 주 목표 3이 들어간 것을 API로 확인
  - 다른 기기인 것처럼 서버에 러닝 1건을 넣고 [지금 동기화] → 기록 탭에 그 러닝이 생기고 상세에 경로 · 구간 표가 보임
  - 서버에서 그 계정의 리프레시 토큰을 지우고 앱을 다시 켬 → 내 정보 탭 "다시 로그인이 필요해요" → [다시 로그인](이메일이 채워져 있음) → 로그인 → 동기화 상태 → 뒤로 가기 → 내 정보 탭
  - 서버를 끄고 [지금 동기화] → "서버에 연결하지 못했어요. 인터넷이 되면 다시 올라가요."
  - 서버를 다시 켜고 러닝을 하나 끝냄 → 완료 요약이 뜨는 사이 서버에 그 러닝이 올라감(8건)
  - [로그아웃] → 확인 창 → "계정이 연결되지 않았어요", 기록 탭의 기록은 그대로
- 확인하지 못한 것: 실기기(같은 와이파이의 PC 서버 주소로), 인터넷이 없는 곳에서 뛴 뒤 돌아와 올라가는지, 서버가 거절하는 러닝(409 · 422)이 있을 때의 화면, 24시간 넘는 러닝, 기록이 수백 건일 때 내려받기에 걸리는 시간, 화면을 읽어 주는 기능(TalkBack)으로 입력 칸 읽기
