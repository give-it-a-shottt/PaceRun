## 최종 판정 (AI 위임 판정 — 사용자 확인 전)
- 수용할 지적과 이유: [주의] 2개 전부와 [제안] 가운데 아래 셋을 뺀 전부.
  - 자정 타이머: 울릴 때마다 다시 읽고 다음 자정을 다시 건다. 남은 시간 계산은 계산 쪽(`week.ts`)으로 옮겨 테스트했다.
  - 알림 예약: 테스트 10개를 만들었다(끔 · 틀린 모양 · 권한 없음 → 권한이 생긴 뒤 예약 · 같은 시각이면 다시 요청하지 않음 · 시간 바꾸기 · 예약 실패 뒤 다시 시도 · 지우기 실패 · 연달아 불렀을 때의 순서 · 껐다 켜기). 고치면서 동작도 바꿨다: 이미 그 시각으로 맞춰져 있으면 폰에 다시 요청하지 않고, 예약할 때 먼저 지우지 않는다(같은 이름으로 바꿔 넣는다 — 실패해도 있던 알림이 남는다).
  - 온보딩 저장 규칙을 서비스(`services/onboarding.ts`)로 옮기고 테스트 5개를 붙였다(어느 단계에서 실패하든 "온보딩 끝"을 적지 않는다).
  - 주 연속 계산은 러닝을 한 번만 훑어 주별로 세게 바꿨다.
  - 쉬는 요일 카드에도 글자 버튼 "다른 운동으로 뛰기"를 더했다(완료 상태의 "한 번 더 뛰기"와 같은 이유 — 홈이 러닝을 시작하는 유일한 곳이다). 피그마에 없는 요소라 feature.md에 적었다.
  - 타입 한 곳으로, 문구의 숫자는 값에서 만들고, 선언 순서를 바로잡았다. feature.md에 형광펜 · 알림 권한 재요청을 적었다.
- 거절할 지적과 이유:
  - 앱 복귀 구독을 공용 훅으로 묶기: 세 곳의 쓰임이 다르다(항상 / 화면이 보이는 동안만 / 화면이 떠 있는 동안). 한 훅으로 묶으면 조건 인자가 늘어 네 줄짜리 구독보다 읽기 어려워진다.
  - 다시 읽기가 두 번 겹치는 것: 읽기는 가볍고(요약 칸만), 늦게 끝난 요청은 버리게 돼 있어 화면이 틀어지지 않는다.
  - 홈의 "가장 최근 요청만 받기" 테스트: 화면 훅을 테스트에서 띄우는 도구가 없다(D-001). 판단이 번호 비교 한 줄이라 순수 함수로 뺄 만큼의 내용이 아니다.
- 다음 기능으로 넘긴 지적: 알림 권한이 꺼져 있을 때 사용자에게 알리기 → 설정 화면(F-007)의 알림 시간 줄에 안내를 넣는다(온보딩에서는 권한 창이 이미 한 번 더 뜬다).
- 다음에 고칠 것: Q-010 · Q-005의 답에 따라 횟수의 단위와 지난 주의 목표 기준을 맞춘다.
