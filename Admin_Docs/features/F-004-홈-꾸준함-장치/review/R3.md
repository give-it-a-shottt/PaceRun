## 지적 (있을 때)
- [주의] [확실] 온보딩 3단계가 "일부만 저장된" 경우를 놓친다. `weeklyGoal` · `reminderTime` 저장이 실패해도 `onboardingDone`만 저장되면 홈으로 넘어간다. 실패 토스트는 뜨지만 주 목표(기본 3)와 알림(꺼짐)이 사용자가 고른 값과 다른 채로 온보딩이 끝난다 — `app/src/app/onboarding/goal.tsx` `start()`의 "onboardingDone만 확인" 부분 — 확인: patch 전체 + `state/settingsStore.ts` `update`(실패해도 throw하지 않고 그 키만 되돌림) — 고치는 방법: 세 번 저장한 뒤 store의 `weeklyGoal` · `reminderTime` · `onboardingDone`이 모두 고른 값과 같을 때만 넘어간다(하나라도 다르면 화면에 남기기). 또는 앞의 두 키가 반영된 것을 확인한 뒤에만 `onboardingDone`을 저장한다.
- [주의] [확실] `parseReminderTime`(저장된 문자열 → 시각, 모양이 틀리면 null)에 테스트가 없다. 온보딩 초기값과 `syncReminder`가 이 함수의 null/정상 판단에 의존한다 — `domain/reminderTime.test.ts`(import 목록에 없음) — 고치는 방법: "07:30" 정상, null, "7:30" · "24:00" · "07:60" · "" 같은 틀린 모양 → null, "00:00" · "23:59" 경계 케이스 추가.
- [제안] [확실] 계획 읽기의 "목표값이 망가진 줄 건너뛰기"와 "모드 ≠ config.mode 줄 건너뛰기"는 코드로는 처리하지만 테스트가 없다(SQL과 한 함수에 섞여 있어 테스트하기 어렵다) — `db/planRepo.ts` `listPlanItems` — 고치는 방법: 줄 배열을 `PlanItem[]`으로 바꾸는 부분을 순수 함수(예: `parsePlanRows`)로 빼서 JSON 깨짐 · 모드 어긋남 · 정상 줄을 테스트한다.
- [제안] [확실] 계획의 `weekday`가 0~6 밖이거나(망가진 값) 오늘 요일 칸이 없으면서 다른 계획도 오늘 이후에 못 찾는 경우 쉬는 날 문구가 "다음 러닝은…" 없이 공백으로 시작한다(`nextPlannedText`가 ''를 돌려줌). `listPlanItems`는 `weekday` 범위를 검사하지 않는다 — `domain/home.ts` `nextPlannedText` · `db/planRepo.ts` — 고치는 방법: `listPlanItems`에서 `weekday`가 0~6 정수인 줄만 받고, 문구는 빈 문자열일 때 이어 붙이지 않는다.
- [제안] [확실] 알림 권한을 거부하면 알림 시간은 저장되지만 예약은 조용히 건너뛴다(`syncReminder`가 false 반환, 호출한 쪽은 값을 안 봄). 나중에 OS 설정에서 권한을 켜고 앱으로 돌아와도 앱을 다시 켜거나 알림 시간을 바꾸기 전에는 다시 예약되지 않는다 — `services/reminder.ts` · `app/_layout.tsx` effect — 고치는 방법: 앱이 active로 돌아올 때도 `syncReminder`를 부르거나, 권한이 없을 때 설정 쪽에서 안내한다(F-007과 함께 정해도 됨).
- [제안] [추정] `syncReminder`를 짧은 간격으로 두 번 부르면(예: 설정에서 시간 − / + 를 빠르게 누름) 두 호출의 취소 → 예약이 섞여 오래된 시각이 마지막에 예약될 수 있다. 같은 identifier라 개수는 늘지 않는다. 지금 화면(온보딩은 저장 시 한 번)에서는 일어나지 않는다 — `services/reminder.ts` — [확실]이 되려면: 설정 화면(F-007)에서 연속 변경 시 `scheduleNotificationAsync`가 나중에 끝나는 쪽이 이기는지 실행해 본다 — 고치는 방법: 호출을 직렬화(이전 호출이 끝난 뒤 최신 값으로 한 번)한다.
- [제안] [확실] 앱을 켜 둔 채 화면이 한 번도 포커스를 잃지 않고 자정을 넘기면(충전 중 켜 둠 등) "오늘"이 바뀌지 않는다. 앱이 background → active가 되거나 탭을 옮기기 전까지 어제 값으로 남는다 — `components/home/useHomeView.ts` — 고치는 방법: 다음 자정에 맞춘 타이머로 `reload`를 한 번 더 부른다.
- [제안] [확실] 배터리 최적화 확인이 실패하면(`isBatteryOptimized`가 false로 대신 답함) "배터리 최적화가 해제됐어요 · 기록이 끊기지 않아요"가 뜬다. 확인하지 못한 것을 해제된 것으로 말한다 — `services/permissions.ts` `isBatteryOptimized` · `app/onboarding/battery.tsx` — 고치는 방법: 확인 실패는 "알 수 없음"으로 따로 두고 안내(설정 열기 · 건너뛰기)를 그대로 보여 준다.
- [제안] [확실] 주 계산 코드는 서머타임을 고려해 짰다고 적었지만(`week.ts` 주석) 서머타임 시간대에서 도는 테스트가 없다. 테스트는 실행 PC 시간대(한국, 서머타임 없음)에서만 돈다 — `domain/home.test.ts` "주 계산" — 고치는 방법: 서머타임 전환 주(예: 미국 3월 둘째 일요일, 시간대를 `TZ` 환경변수로 고정)에서 `startOfWeek` · `addDays` · `weekCells` 결과를 확인하는 테스트 1~2개를 추가한다.
