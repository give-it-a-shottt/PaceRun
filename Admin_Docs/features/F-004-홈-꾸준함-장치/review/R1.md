## 지적 (있을 때)
- [주의] [추정] 온보딩 3단계의 저장 성공 판정이 `onboardingDone` 하나만 본다. `weeklyGoal` 또는 `reminderTime` 저장이 실패해 되돌려져도 `onboardingDone`만 저장되면 홈으로 넘어가 고른 값이 조용히 사라진다 — `app/src/app/onboarding/goal.tsx` `start()` — 패킷의 diff와 "update는 실패한 키만 되돌리고 토스트"라는 설명만 읽었고 `settingsStore.update`는 열지 않았다 — `update`가 실패를 던지는지 값으로 알려 주는지 열어 확인하면 [확실]이 된다. 고치는 방법: 세 키의 성공 여부를 모두 보거나, 세 값을 한 번에 저장하는 서비스 함수로 옮겨 "전부 성공했을 때만 true"로 판정한다. 저장 흐름이 화면에 있다는 점도 함께 정리된다(architecture.md의 "화면은 서비스를 부르기만 한다").
- [제안] [확실] 오늘의 러닝 카드 종류별 버튼 문구가 두 곳에 나뉘어 있다. `noPlan`의 "자유 20분 시작"은 domain(`TodayCard.startLabel`)에서 오고, "가볍게 10분 뛰기" · "기록 보기" · "시작"은 `home.tsx`의 `actions()`에 박혀 있다 — `app/src/app/(tabs)/home.tsx` `actions()`, `domain/home.ts` `todayCard()` — 두 파일의 diff 전체를 읽었다 — 고치는 방법: 문구를 한쪽(domain의 `TodayCard`)에 모으면 화면은 종류별로 어떤 버튼을 그릴지만 고른다. `actions()`가 40줄 가까이 되는 것도 같이 줄어든다.
- [제안] [확실] 같은 러닝으로 형광펜을 한 번만 칠하는 판단이 컴포넌트 파일의 모듈 변수(`lastPaintedKey`)에 들어 있다. 앱이 살아 있는 동안만 기억하는 전역 상태인데 `state/` 밖에 있고 화면 부품 안에 숨어 있어 찾기 어렵다 — `app/src/components/home/WeekCells.tsx` `PaintedBand` — 파일 전체를 열어 읽었다 — 고치는 방법: 의도한 동작이면 지금 그대로 두되 주석에 "앱을 다시 켜면 다시 칠해질 수 있음"을 적거나, 작은 store/훅(`state/`)으로 옮겨 이름을 붙인다.
- [제안] [확실] "버튼이 로딩으로 바뀌기 전에 한 번 더 눌러도 두 번 실행되지 않게 하는" `useState` + `useRef` 쌍이 두 화면에 똑같이 복붙돼 있다 — `app/src/app/onboarding/index.tsx` `allow()`, `app/src/app/onboarding/goal.tsx` `start()` — 두 파일 diff를 읽었다 — 고치는 방법: `useSingleFlight` 같은 작은 훅으로 뽑는다. 세 번째로 필요해질 때 해도 된다.
- [제안] [확실] `plannedCard()`가 "지난번 페이스"를 찾으려고 가짜 현재 기록(`startedAt: now, avgPaceSecPerKm: null`)을 만들어 `previousComparable`에 넘긴다. 읽는 사람이 왜 가짜 값을 넣는지 한 번 더 생각해야 한다 — `app/src/domain/home.ts` `plannedCard()` — diff 전체를 읽었다 — 고치는 방법: `previousComparable`의 첫 인자를 `{ mode, startedAt }`만 받게 줄이거나, 이유를 한 줄 주석으로 남긴다.
- [제안] [확실] 죽은 코드와 앞서간 주석이 조금 있다. `nextPlannedText()`의 마지막 `return ''`은 계획이 있으면 닿지 않는다(호출부에서 `plan.length === 0`을 먼저 걸러 낸다). `compare.ts`의 머리 주석은 "완료 요약, 러닝 상세가 함께 쓴다"고 하는데 둘 다 아직 없다(F-006) — `app/src/domain/home.ts` `nextPlannedText()`, `app/src/domain/compare.ts` 맨 위 — diff를 읽었다 — 고치는 방법: 닿지 않는 줄은 두고 주석으로 "계획이 있으면 닿지 않는다"를 적거나 지우고, 주석은 "홈의 완료 카드가 쓴다. 완료 요약 · 상세에서도 쓸 예정"으로 바꾼다.

- 프론트 구조: 컴포넌트 책임이 하나인가 → `home.tsx`, `onboarding/*.tsx`, `useHomeView.ts`, `WeekCells.tsx`, `TodayCardView.tsx`(직접 열었다) → 그리기와 계산은 잘 갈렸다(계산은 `domain/home.ts`). 다만 `goal.tsx`에 저장 흐름이, `home.tsx`에 버튼 문구가, `WeekCells.tsx`에 "한 번만" 판단이 섞여 있다(위 지적)
- 프론트 구조: 폴더 구조가 overview/architecture.md와 맞는가 → architecture.md 폴더 · 의존 방향 절과 diff의 import 목록 → 맞다. 라우트는 `src/app/`, 홈 부품은 `components/home/`, 알림 · 홈 읽기는 `services/`, SQL은 `db/planRepo.ts`, 계산은 `domain/`이다. `domain/*`은 React · Expo를 import하지 않는다. 의존은 화면 → 서비스 → db → domain으로 한쪽으로만 흐른다
