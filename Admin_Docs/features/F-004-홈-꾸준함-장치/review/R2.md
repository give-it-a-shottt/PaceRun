## 지적 (있을 때)
- [제안] [확실] 온보딩 화면에 "이미 마쳤으면 홈으로" 막는 장치가 없다. 앱 주소(`pacerun://onboarding`, `pacerun://onboarding/goal`)로 언제든 다시 들어갈 수 있다. 3단계는 알림을 항상 "켜짐"으로 열기 때문에(`enabled: true`), 알림을 꺼 둔 사용자가 다시 들어와 [시작하기]를 누르면 알림이 다시 켜지고(저장된 시각이 없으면 오전 7:00) 주 목표도 다시 저장된다. 다른 앱이 주소를 열어 줄 수는 있지만, 사용자가 직접 누르지 않으면 값은 바뀌지 않는다. 반대 방향(`pacerun://home`으로 온보딩 건너뛰기)은 `onboardingDone`이 false로 남아 다음 실행 때 온보딩이 다시 나오고, 권한은 러닝 시작 때 다시 묻는다. 해가 없다 — `app/src/app/onboarding/_layout.tsx` · `onboarding/goal.tsx`(`useState<ReminderChoice>` 첫 값), `app.json` `scheme: "pacerun"` — 확인한 범위: 6d07d63의 onboarding 3개 화면 · 레이아웃 diff, app.json, `app/index.tsx`의 분기 — 고치는 방법: `onboarding/_layout.tsx`에서 `onboardingDone`이면 `<Redirect href="/home" />`로 보낸다. 다시 들어오는 것을 허용할 생각이면, 3단계 알림 스위치의 첫 값을 저장된 `reminderTime`이 있는지에 따라 정한다.
- [제안] [확실] 홈이 보일 때마다(탭 포커스 · 앱 복귀) `listFinishedRuns()`가 끝난 러닝 전체를 `SELECT *`로 읽는다. 줄마다 `JSON.parse(config_json)`도 하는데, `describeHome()`은 `config`를 쓰지 않는다(`FinishedRun`에 config 칸이 없다). 수천 건일 때 이 읽기와 파싱이 홈을 열 때마다 JS 스레드에서 되풀이된다(걸리는 시간은 재지 않았다 — 패킷에서도 "확인하지 못한 것"이다). 또 `toRecord`의 `JSON.parse`는 실패를 잡지 않아서, config_json이 망가진 줄이 하나만 있어도 홈 전체가 "기록을 불러오지 못했어요"가 된다. `planRepo`는 망가진 줄을 건너뛰는 것과 다르다 — `services/homeData.ts` `loadHome()` → `db/runsRepo.ts` `listFinishedRuns()` · `toRecord()` — 확인한 범위: homeData · runsRepo · home.ts의 `FinishedRun` 타입, schema.ts의 인덱스(`idx_runs_started_at`가 있음) — 고치는 방법: 홈 전용으로 필요한 칸만 읽는 함수를 runsRepo에 둔다(id · mode · plan_label · started_at · elapsed_ms · distance_m · avg_pace_s_per_km · counted, config 파싱 없음). 그러면 파싱 비용과 망가진 줄 하나 때문에 홈 전체가 실패하는 문제가 함께 없어진다.
