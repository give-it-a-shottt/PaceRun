# 리뷰어 공통 지시

메인이 리뷰어 서브에이전트를 띄울 때 이 파일과 자기 체크리스트(R1~R4.md 중 하나)를 읽게 한다.

## 지킬 것

1. 자기 체크리스트로만 판단한다. 다른 리뷰어의 결과, 같은 기능의 이전 회차 결과(review/ 폴더의 기존 파일, git 기록)는 보지 않는다.
2. 메인이 준 리뷰 패킷(작업 요약 · 바뀐 파일 목록 · diff 보는 명령 · 설계 의도 · 관련 문서 위치 · 테스트 결과)을 기준으로 본다. 패킷의 diff 명령은 그대로 실행해도 된다. 패킷으로 판단이 안 되는 항목만 해당 파일을 직접 연다. 레포 전체를 탐색하지 않는다.
3. 테스트 · 빌드를 다시 돌리지 않는다. 패킷의 테스트 결과를 근거로 쓴다.
4. 코드 · 문서를 고치지 않는다. 쓰는 파일은 지정된 결과 파일 하나뿐이다.
5. 지적을 억지로 만들지 않는다. 없으면 "지적 없음"이다.
6. 디자인(색 · 간격 · 폰트 · 컴포넌트 모양 · 반응형 레이아웃 · 접근성 · 색 대비)은 지적하지 않는다.
7. 민감 정보(키 · 비밀번호 · 토큰 · .env 값 · DB 접속 정보 · 개인정보)는 값을 옮겨 적지 않는다. 위치만 적는다.
8. 열린 질문의 임시 처리 때문에 생긴 문제는 지적 대신 "Q-00X 임시 처리와 관련"이라고 적는다.
9. `(AI 위임 결정)` · `(AI 초안 — 사용자 위임)` 표시는 사용자가 맡긴 것이라 그 자체는 지적하지 않는다.

## 등급과 확신

- [위험]: 그대로 두면 잘못 동작하거나 보안 문제가 생긴다. [주의]: 지금은 돌아가지만 고치는 게 좋다. [제안]: 해도 되고 안 해도 된다.
- [확실]: 해당 코드를 직접 읽고(패킷의 diff 또는 직접 연 파일) 문제를 확인했다. 테스트 실패처럼 결과로 드러난 것도 [확실]이다.
- [추정]: 일부만 보고 판단했거나, 관련 파일을 열지 않았거나, 실행해 보지 않으면 확실히 알 수 없다. "무엇을 확인하면 [확실]이 되는지"를 고치는 방법 앞에 적는다.
- 확인하지 않은 것을 [확실]로 쓰지 않는다. 지적마다 확인한 범위를 짧게 쓴다.

## 결과 파일 형식 (그대로 지킨다)

```
AI 근거용 — 사용자는 안 읽어도 됨

리뷰어: R{n} {관점}
회차: {N}차 (YYYY-MM-DD)
모델: {실제로 쓴 모델}
판정: 지적 있음 / 지적 없음

## 지적 (있을 때)
- [위험|주의|제안] [확실|추정] 내용 — 위치(파일·함수) — 확인한 범위 — 고치는 방법

## 체크 항목별 근거 (항상 작성, 항목당 한 줄)
- 항목 → 확인한 위치 → 결과
- 항목 → 해당 없음 (이유: …)
- 항목 → 미확인 (이유: …)
```

- 체크리스트의 모든 항목을 한 줄씩 다룬다. 쉼표로 나열된 세부 항목은 각각 한 줄로 쓴다.
- 지적이 없는 항목에 설명을 덧붙이지 않는다.
- [신규] 표시는 메인이 붙인다. 리뷰어는 붙이지 않는다.
